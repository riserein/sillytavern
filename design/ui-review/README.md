## 第一阶段：当前界面审查

### 页面与组件

正式版有播放、曲库、导入、最近播放、播放排行、外观六个页面。曲库包含总曲库、默认曲库、自建歌单、歌单管理、角色绑定及成员选择；导入包含本地/直链、在线搜索、分享链接。浮层包括歌曲详情、播放队列、透明歌词、背景裁剪、磨砂选择菜单和字体预览。

主要文件：`index.js` 构造界面、管理页面/弹层、接入音频及角色事件；`style.css` 管理样式；`player-components.js` 是黑胶底栏；`appearance.js`、`scheme.js`、字体和背景模块负责个性化；`floating.js`、`resizing.js` 负责指针/键盘操作；`core.js` 负责曲库/歌单/绑定/历史；`local-store.js` 保存 IndexedDB 文件；`online-panel.js` 与 `platforms/` 接入在线能力。已有核心逻辑无需为了视觉改造整体重写。

### 发现的问题

| 问题 | 代码/真实界面证据 | 对使用的影响 | 建议 |
| --- | --- | --- | --- |
| 样式规则层层覆盖 | 同一个 cover、mini、details、font 控件在 CSS 多处重新定义；例如 mini 曾设 56px，又在尾部改 44px | 新改动容易受到旧规则、宿主和选择器优先级影响 | 整理为变量、基础组件、布局、主题、响应式、状态六层；逐步替换，不一次删除全部旧规则 |
| 曲库缺少查找工具 | `renderTracks()` 直接输出整个当前集合；没有搜索/排序/筛选状态 | 歌曲多时只能滚动 | 加搜索、来源/播放能力筛选、视图排序；原型已提供轻量演示 |
| 歌曲行操作拥挤 | 真实曲库每行有 5 个 button，含标题按钮；右边常驻更多、加入/移除、删除和播放 | 窄屏挤压歌名，删除操作过于显眼 | 行内留播放和更多；详情中提供加入歌单、封面/歌词、移除/删除，危险操作仍确认 |
| 触控区域偏小 | 实测行播放键 29×30px、关闭键 30×30px，导航 10px 字体，见 [原始测量](baseline-metrics.json) | 手机上容易点错 | 正式设计目标主要操作 44px 以上；底栏保持约 44px 总高；图形与可点击区分开计算 |
| 按网页宽度而非窗口宽度适配 | 当前主要断点是 `@media(max-width:600px)` | 大屏里的小悬浮窗仍可能使用大屏规则 | 按容器宽度与实际高度重排，Container Queries + ResizeObserver 回退 |
| 小窗口中封面挤压播放键 | 播放页纵向堆叠大封面、标题、时间、控制和歌单导航 | 核心控制需要滚动才看到 | 大窗横向或侧栏，窄窗居中，矮窗缩封面；先保证播放、切歌与进度 |
| 歌单信息分散 | 名称、数量、封面、角色绑定分布在标题/管理区/曲库首页 | 不容易判断“这张歌单给谁听” | 歌单头部集中展示封面、名称、数量、简介与绑定状态，附近保留管理入口 |
| 查看歌单与切换播放来源共用状态 | `browseCollection()` 可能调用 `activatePlaylist()`，后者会暂停音频 | 只是浏览另一张歌单也会打断听歌 | 正式版区分“正在浏览”和“正在播放”；角色切换仍按已有规则暂停、手动播放。原型保持原有业务行为，未悄悄改写 |
| 队列没有独立模型 | `renderQueue()` 使用 `getQueue(settings)`，其成员来自当前永久歌单/总库 | 直接给队列加删除/排序可能误改永久歌单 | 单独建立临时队列快照，队列移除不删文件、排序不改歌单；这一项待确认后开发，不用假按钮假装已做 |
| 歌词高亮改变字号 | 普通歌词 18px，当前句 20px；滚动通过位置差直接设置 scrollTop | 换句/长行可能改变布局，造成跳动 | 保持同一字号，通过字重、颜色、透明度强调；平滑跟随并考虑用户手动滚动 |
| 设置页是一条长表单 | 所有字体、背景、颜色、透明度、窗口与偏好在同一长页 | 找某个选项时需要反复翻找 | 分组为文字、颜色材质、图片、窗口与偏好，可折叠，但所有能力仍保留 |
| 状态反馈不成体系 | 普通提示、搜索错误、播放失败、空页面分散，部分文字很长 | 不容易区分“没有结果”和“来源暂时失败” | 单独的加载/空/失败/受限状态，短说明加可执行的恢复入口；不暴露堆栈 |
| 播放动效不应仅依赖播放意图 | 当前状态主要参考 `audio.paused/ended`，`play` 早于真正 `playing` | 缓冲时可能先表现成正在播放 | 正式版明确 idle/loading/playing/paused/error，只有实际 playing 驱动唱片和记录；不得伪造在线播放 |

实测对照来自独立浏览器与测试账户，宿主设置保存已隔离；没有在用户日常酒馆上做破坏性操作。

### 可以保留的特色

- 黑胶底栏、唱片中间的歌曲封面、播放旋转/暂停保持角度和慢速长标题。
- 可拖浮球、可拖/缩放的窗口、边界限制、键盘操作及保存的位置尺寸。当前可独立拖的是浮球与窗口，底栏随窗口移动；没有把它误说成独立可拖的窗口。
- 大封面与点击切换透明歌词、角色歌单、独立总库/默认库、六组配色、材质、透明度、背景裁剪和字体预览。
- 三分之二底部详情/队列，以及已经具备的焦点管理、Esc 和滚动区域。

### 必须保留的入口与数据

正式开发时保留全部六页和三个导入入口，保留自建歌单、来源预览与选择导入、默认库隐藏/复制、多个角色绑定、封面/歌词编辑、历史/排行和完整个性化。把按钮收进更多菜单属于改入口，不是删功能。

不改本地文件 blob ID、IndexedDB 数据库、曲目 ID、现有歌单 ID、角色 avatar 标识和历史记录格式。新建浏览状态与临时队列优先放在独立 UI/session 状态中；确需持久字段才增加向后兼容的可选字段，并测试旧数据迁移。

## 第二阶段：两套视觉方向

两套方案不只是更换配色，主要区别在版面、导航、密度与字体气质。它们都可继续使用旧主题、字体和用户背景；A 默认日间、B 默认夜间不代表锁死深浅模式。

| 设计维度 | A：纸上听音 | B：夜航听音 |
| --- | --- | --- |
| 整体风格 | 温暖、疏朗，接近阅读一本唱片册；音乐与故事并置 | 安静、紧凑，接近桌边的一台听音设备；控制与内容清晰分区 |
| 默认配色 | 米纸 `#F4F0E7`，墨灰 `#2F302A`，陶土棕 `#97583F` | 深墨绿 `#182220`，浅灰白 `#E8EEE6`，鼠尾草 `#B2C3B1`；不用高饱和荧光色 |
| 背景/材质 | 默认柔和雾面、细分割线、轻边框；图片作为背景时增加阅读遮罩 | 默认深色雾面、低对比层级；浮层略实一些，避免字落在复杂图上 |
| 字体层级 | 默认页面/曲名用宋体气质，正文用设备字体；自定义字体优先，不强制覆盖 | 默认无衬线，标题更利落；同样尊重用户选择的宋体/像素/导入字体 |
| 主播放器 | 大窗封面左、信息与控制右；下方只保留播放来源、队列与角色提示 | 大窗左侧竖向导航，播放区居中；封面、歌名、进度、控制按主次纵向展开 |
| 我的音乐 | 总库/默认库在前，自建歌单大窗双列、小窗单列；封面更有收藏册感觉 | 以整齐的单行列表为主，减少边框，适合歌单较多的人 |
| 歌单详情 | 封面、名称、简介、数量及角色集中；查找工具在歌曲上方，次要操作入详情 | 同样的信息完整性，视觉更紧凑；管理入口与播放入口明确分开 |
| 黑胶迷你 | 贴底约 44px，黑色纹理唱片搭配纸色底；点击歌名/唱片回播放页 | 深色细边框、薄底栏，唱片标签是主要色彩；折叠浮球也使用同一唱片视觉 |
| 手机/小窗 | 切为居中封面，导航用短标签+图标；按实际高度缩封面，先露播放控制 | 宽窗侧栏收成上方导航；其余采用同一触屏规范，避免窄窗硬塞侧栏 |
| 动效 | 160ms 页面淡入、180ms 封面/浮层，点击反馈轻；歌词不改变字号 | 动效时间统一，位移更少；状态通过颜色、真实播放与图标变化表达 |
| 更适合 | 喜欢宋体、角色氛围、温润浅色与较舒展版面 | 常用夜间主题、长时间听歌、偏好紧凑与克制控制布局 |

推荐以 **A 的信息层级和操作流程** 为基础，是否采用 A 的温暖气质由你决定；也可以选择 B，或组合“A 的版面 + B 的材质”，不擅自替你定最终方向。

## 共用的设计与交互规范

- 颜色采用语义变量：主/次背景、浮层、主要/次要/弱文字、强调色、边框/分割线、悬停/选中/禁用、成功/警告/错误。原型 `--ux-*` 引用现有 `--stm-*`，正式版确认后整理为一套，避免长期保留两套叠加。
- 排版目标：主歌名 22–28px、页标题 23–24px、歌单标题 20–22px、行标题 13–14px、说明 11–12px、时间 11px。自定义字体可能改变字面大小，正式验收会增加极长歌名与导入字体用例。
- 间距采用 4/8/12/16/24/32；控件圆角 8–10，窗口 12–20，唱片与播放键保留圆形；阴影只服务于悬浮层级。
- 所有行以封面、标题、作者/来源、真实能力和播放状态为主。来源受限项显示限制/来源入口，不放点了必然失败的播放键。
- 分享导入固定显示所选数、原始总数与剩余容量；正式阶段让确认按钮随选择/容量变更而禁用或更新文案，保持现有整批拒绝及显式选择逻辑。
- 队列正式版区分“正在播放 / 接下来 / 最近听过”，支持临时调整；不把队列排序保存到永久歌单。用户明确进入歌单编辑时才改变永久顺序。
- 歌词保持透明全窗、点击返回；统一行高、自动换行、当前句强调和减少动态效果。未来增加用户手动浏览歌词后的跟随恢复，不能抢滚动。
- 页面切换不停止音乐；主动换播放来源/角色卡仍遵守原有“暂停、手动播放”。图标必须有文字或可访问名称；不依赖悬停才能发现主要操作。
- 所有动效只在状态变化时触发，不用持续 JavaScript 动画循环；唱片用 CSS transform + animation-play-state，减少动态效果时关闭，背景不做持续昂贵动画。

## 原型实现边界与验证

原型由 `build.mjs` 将当前根目录与 `platforms/` 模块打包到 HTML，复用实际 DOM 和现有播放/角色逻辑；只在临时副本替换存储为内存 Map，嵌入现有封面缩略图，并用 `bootstrap.js` 提供示例宿主接口、模拟角色及合成音。新增界面调整在 `preview.css`、`preview.js`，不进入 manifest，也不修改正式模块。

已提供：两种版面、缩放重排、单页曲库搜索/筛选与显示排序、精简行操作、详情操作、歌单头部、设置分组、透明歌词层级、唱片浮球/底栏和动效。显示排序只作用于原型列表；临时队列重排、正式批量管理、简介持久化、浏览与播放状态分离仍属于确认后开发内容，原型没有用空按钮宣称实现。

浏览器验证使用真实 HTML Audio 播放生成 WAV，不是伪造“正在播放”。两套方案都检查：页面切换继续播放、角色切换暂停、主页暂停、曲库查找/能力筛选、详情加入歌单、黑胶暂停保持角度、窄屏边界和减少动态效果；结果见 [preview-validation.json](preview-validation.json)。原有 57 项单元测试也全部通过。这证明原型交互可用，不代表正式 UI 升级验收或商业在线音乐实测。

重建与复测（在安装开发依赖的仓库中）：

```sh
node design/ui-review/build.mjs
CHROMIUM_PATH=/usr/bin/chromium node design/ui-review/verify.mjs
```

重建使用固定版本 esbuild 0.25.10 作为临时工具，不增加项目依赖或 UI 框架。复测需按项目 README 启动独立测试酒馆来提供静态文件；脚本访问原型页面，不访问宿主设置 API。环境浏览器禁用了 file URL，截图通过测试酒馆静态目录生成；普通浏览器下载 HTML 可直接查看。封面缩略图来自仓库原有 MIT 插画，没有引入第三方私有 UI/图片。

## 确认后才执行的正式开发

1. 统一设计变量、基础控件及状态，不改变存储格式。
2. 主播放器、黑胶底栏与折叠浮球。
3. 曲库查找、歌单编辑/排序/批量管理、角色入口。
4. 在线搜索、分享预览与能力/失败状态。
5. 详情、歌词和独立临时队列；增加必要逻辑与迁移测试。
6. 设置、主题、背景、字体和容器自适应。
7. 动效/性能，桌面大/小窗与手机的截图对比及全部旧功能回归。

在线播放问题仍单独保留：Openverse 安全验证、云端 Chromium 证书信任、Audius 未配置 Key 和商业平台使用限制都没有因做原型而消失。没有重试被拒绝的证书导入，没有改平台开关，没有把示例音当作平台播放成功。确认 UI 方案后仍须继续处理真实播放，并按现有真实检查入口单独验收。

**下一步等你选择 A、B 或明确的组合意见。未确认前不应用候选样式到正式播放器。**
