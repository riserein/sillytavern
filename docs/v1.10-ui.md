# 1.10.0：B「夜航听音」正式实施

用户确认 B 后，在 v1.9.0 / `56dc13e` 基线上继续开发，没有重新制作播放器或更换存储。安装地址仍是原仓库，不提供额外离线安装包。

## 实际变更

| 文件 | 作用 |
| --- | --- |
| `player-ui.js` | 独立的展示层：图标导航、控制区、唱片浮球、实际播放/加载状态、设置分组、封面有限过渡及容器尺寸观察。不读写存储、不请求曲库、不自行播放。 |
| `night-ui.css` | 正式样式入口，引用原 `style.css` 保留旧组件，再应用 B 的语义变量、尺寸、侧栏/顶部导航、歌词层级、浮层和减少动态效果；选择器限制在插件内。 |
| `index.js` | 接入视图；分开浏览歌单与播放来源；模型过滤/排序与批量操作；详情中的完整操作入口；歌单简介、永久顺序编辑和临时队列。 |
| `playback-queue.js` | 页内队列快照，移除、移动、恢复、按 ID 合并新歌、清除已删歌曲、本轮真实播放标记；不写永久歌单。 |
| `core.js`、`scheme.js` | 增加夜航预设与日夜调色；歌单简介为至多 240 字的可选字段，旧数据无需破坏性迁移。 |
| `manifest.json`、包版本文件 | 1.10.0；无需构建即可由酒馆加载新样式与模块。 |
| 测试与文档 | 三项队列/兼容单元用例、三项新浏览器场景，旧浏览器用例调整新入口路径；更新 README 和 CHANGELOG。 |

默认夜航为深墨绿、鼠尾草与浅灰白，背景材质仍由用户选择。首次安装采用 B 配色与宽窗；**已有用户的配色、日夜模式、字体、背景、透明度、音量、位置和尺寸保持原值**。因此已有用户更新后可能看到 B 的布局搭配自己的旧颜色；在“外观 → 配色与材质”选“夜航”，并按需要选夜间即可获得深色方案。

## 可直接使用的流程

- 宽窗侧边导航，窄窗回到顶部导航；按实际播放器宽高调整封面，矮窗优先显示进度和播放控制，不按整张网页宽度硬判断。
- 曲库搜索歌名/歌手，按歌名/歌手显示排序，按来源/播放能力筛选。显示排序不写永久歌单，也不按同名歌曲合并不同录音。
- 行内仅保留歌曲、播放及更多；更多弹层中可播放/暂停、加入歌单、仅移除当前成员、确认后删除曲库歌曲，以及完整封面/歌词编辑。受限来源没有假播放按钮，原许可与官方来源仍可查看。
- 歌单头部显示封面、标题、数量、简介和实际绑定角色名称；管理中可修改简介及永久顺序，原封面/改名/多角色绑定/删除入口保留。
- “批量管理”可选择筛选结果或逐首选择，加入指定歌单、移除歌单成员或确认后全局删除；默认库复制仍计容量，容量不足整批拒绝，不悄悄少复制。
- 浏览其他歌单、创建歌单不打断音乐；点击其他来源的歌曲或主动切换播放页的来源才改变正在播放的来源。角色切换仍暂停并打开绑定歌单，手动播放；回主页暂停。
- 队列上下移动/移出非当前歌曲只对本页临时队列生效，支持恢复歌单顺序；当前歌曲不可直接移出。新加入来源的歌曲补到尾部，真实全局删除会剔除对应 ID。刷新、主动换播放来源或角色切换重置临时编辑，不持久覆盖永久顺序。
- 歌词保持透明全窗、LRC 同步与点击返回，以颜色/字重强调当前句，字号不再改变；跟随滚动尊重减少动态效果。
- 外观原能力全部保留并按文字、配色材质、背景、窗口偏好分组。旧字体、导入字体与用户图片不因 B 被替换。
- 唱片旋转跟随实际 `playing`，缓冲等待、暂停或错误时停止；暂停保留角度。封面只在切换时过渡，不引入持续 JavaScript 动画循环。

## 验证口径

- `npm run check`：正式模块语法检查。
- `npm test`：原有 57 项，加 3 项队列与旧数据兼容测试。
- `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`：真实酒馆的原有 57 项浏览器场景，加 3 项 B 场景。新场景验证临时队列与永久歌单隔离、浏览不断音、查找/批量加入、简介/顺序刷新恢复、按容器响应、手机主要控件边界和减少动态效果。
- 音频播放、进度、暂停/续播和记录使用真实 HTML Audio 与生成 WAV/MP3；平台搜索/分页/失效等确定性回归继续使用明确的接口替身，不能据此宣布外部服务可播放。
- 缓冲 UI 的事件检查会注入 `waiting` / `playing` 来验证状态响应，不冒充真实外部网络缓冲实测。新 UI 用例选择未连接的聊天后端，避免与音乐无关的 Horde 外网状态请求干扰检查。
- 旧用例改动只因入口迁移（删除/加入移动到详情、新建在音乐总览、明确选择播放来源），保留原来的播放、存储、角色及外观断言。原用户不需要手动迁移 IndexedDB。

语法检查与 **60 项单元测试通过**。浏览器回归中 **60 个不同场景均已通过**：全量运行先通过 58 项，发现底栏间距/整窗意外滚动及受限来源入口名称两处问题；修复后对失败项及受影响的 B 页面、窗口拖动、黑胶底栏、详情进行定向复测，最后一轮 7 项全部通过。没有把初次含失败的全量运行写成一次全绿。

结果汇总见 [机器可读记录](v1.10-validation.json)。手机尺寸/触摸用 Chromium 的视口和触摸模拟验证，尚未在实体 iOS/Android 设备及所有浏览器上逐一验收。

2026 年 10 月 15 日（北京时间）再次执行真实联网检查：未模拟平台接口或音频。正常浏览器路径成功加载正式扩展，但访问 Openverse 被 `net::ERR_CERT_AUTHORITY_INVALID` 阻挡，`fullPlaybackVerified: false`；Audius 未配置公开 Key，Spotify/SoundCloud 候选保持关闭。命令按预期返回非零，原始结果见 [真实联网记录](v1.10-live-verification.json)。另一次显式代理配置尝试未能在 45 秒内加载插件，因此那次没有进入平台测试；未将两种失败算作平台播放成功。

## 在线能力边界继续保留

本轮保留 `online-panel.js`、`platforms/`、默认曲库维护流程及所有导入能力，没有启用未经核实的公共第三方接口或绕过平台限制。Audius 仍待维护者公开 Key，用户已决定暂不提供；商业 SDK/iframe 候选仍按平台限制默认关闭。正式默认曲库保持空，等待开发者选定授权歌曲。

本次 UI 更新不能解除先前 Openverse 验证页、浏览器证书信任和平台权限方面的阻碍；不重新导入被拒绝的代理 CA，不把页面漂亮或本地测试发声称作外部全曲播放。真实检查仍可按 [本机播放验证](live-playback-guide.md) 使用原入口执行。
