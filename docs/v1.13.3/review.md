# v1.13.3 稳定性与安全性审查

基线为 main `b879e430299970306a838f24f634f5849a5db95b`，实读 manifest/package 版本 **1.13.2**。本轮不重做界面，不改旧数据库。已阅读当前存储、草稿、资源回收、原生导出、运行时、网络适配与 v1.13.0/1.13.2 审计及测试。下列行号固定指向基线，后续修复可能移动。各阶段提交及测试会补入本目录。

## 已复现 Bug

### N01 / P2：删除草稿没有版本检查

- 位置：`card-player/project-store.js:85–86`；`card-maker.js:964`。
- 条件：同一项目在页面 A 保存后，页面 B 更新，再由 A 删除；正常 UI 在保存与删除之间也存在这一异步窗口。
- 真实 IndexedDB 最小复现：A 保存 revision 1，B 保存 revision 2，A 删除后 revision 2 也消失。没有把这个受控时序称为真实多人事故。
- 影响：较新的草稿被旧页面删除；旧版的保存冲突保护没有覆盖删除。
- 修复：删除传入预期 revision，在同一 IDB 事务内读版本并比较，不一致则 abort；保留直接低层无版本删除供已核验回滚使用。

### N02 / P2：原生导出包装器错误拦截第三方域名的同路径请求

- 位置：`card-player/native-export.js:395–399`。
- 条件：其他扩展请求 `https://其他域/api/characters/export`，请求体 avatar 与当前某张带标记卡一致。
- 受控浏览器复现：返回本插件 422，原请求没有转发。测试没有联系真实第三方服务器。
- 影响：破坏其他扩展请求，还可能错误触发本机角色保存。不等于已确认凭据外传或服务端 SSRF。
- 修复：同时检查目标 origin、路径及请求方法；其他请求原样转发。

## 源码确定的缺陷 / 上轮风险进入本轮修复

### S01 / P1：草稿与本地 Blob 没有账号命名空间

- 位置：`local-store.js:8`；`card-player/project-store.js:10,81`；`card-maker.js:154,543`。
- 固定数据库及 last-project 键按 origin 全局共享。浏览器实验已确认第二个 Store 能读取第一个 Store 的私有测试草稿；真实 ST 多账号验收在独立资料实例补做，当前不声称已完成。
- 相同资源 ID 被两个账号的设置引用时，一方删除可能破坏另一方资源。普通随机导入不会必然碰撞，旧设置复制/跨账号操作才会触发此条件。
- 这是 v1.13.2 的 R06/R07 等风险的后续处理，不重复算作新发现。计划使用官方 `/api/users/me` 的账号内部 handle + created；不使用显示名称。旧库归属必须经用户明确确认后复制，不自动删除旧库。
- 浏览器同源脚本仍有主页面权限；逻辑隔离不构成抵御恶意扩展的安全沙箱。

### S02 / P2：平台 JSON 读取没有响应字节上限

- 位置：`platforms/request.js:49–53`。
- 已有超时/取消，但仍直接 `response.json()`；快而巨大的响应会在解析前完整读入。没有复现实际外网 OOM。
- 属于上轮 R05 的具体整改，不把缺少测试当新 Bug。修复为有 Content-Length/流累计的限长读取并取消，保留超时/限流/失败后本地可用行为。

## 潜在风险（未确认事故）

- 多标签及服务器设置与 IDB 之间没有跨系统事务；响应丢失不能简单等同保存失败。恢复须 journal + 新资源 ID + 校验/保留待确认状态，禁止先清库。
- 同源账号删除后重建、服务器被替换、官方账号接口缺失；必须使用 created 区分，不能猜默认身份。
- 大卡完整 Helper 流程此前观察到高 RSS；不是手机测量，更不是峰值。须测导入/显示/首播/长任务与进程采样；单纯堆快照不足以评价稳定性。
- 浏览器配额、系统回收、私密模式、后台/锁屏、外部域重定向/失效仍需单列。

## 用户体验缺口 / 新功能

完整二进制备份恢复、资源占用统计、可预览安全清理、旧库归属确认及账号迁移属于本轮新功能，不属于“发现了数据丢失 Bug”。备份只导出播放器白名单数据与资源，排除整个 ST 设置、聊天、Cookie 和凭据。远程音频仅备份元数据/URL，不称离线备份。
