# 大型角色卡性能：实际测量及边界

## 同一原创音频/字体的实际 ST/Helper 流程

测试在 Linux Chromium 154、ST 1.19.0、官方 Helper 4.11.3。首项使用 20 + 8 MiB 合成 WAV、1,531,668 字节所选字体、内置封面，内嵌总量接近 30 MiB。两次随机备用封面选择可能有少量字节差异；均无音频转码。仅各一次观测，没有统计显著性或速度保证。

| 观测 | 改进前 | 改进后阶段构建 |
| --- | ---: | ---: |
| JSON 实际字节 | 42,001,038 | 42,044,349 |
| PNG 实际字节 | 56,076,484 | 56,134,232 |
| JSON 导出 ms | 27,324 | 23,359 |
| PNG 导出 ms | 51,765 | 54,882 |
| 首项作者 renderer isolate 最大观察 JS 堆 MiB | 1507.13 | 1508.48 |
| 首项作者浏览器多进程 RSS 最大观察合计 MiB | 4527.22 | 4530.47 |
| PNG 导入 ms | 20,028 | 20,531 |
| PNG 选角色至 DOM 首次出现 ms | 2841.6 | 2212.5 |
| PNG 选角色至 loadeddata ms | 3047.8 | 2786.2 |
| JSON（改选字体后重导出） 导入 ms | 19,584 | 17,524 |
| JSON（改选字体后重导出） 选角色至 DOM 首次出现 ms | 2578.5 | 2241.7 |
| JSON（改选字体后重导出） 选角色至 loadeddata ms | 2771.7 | 2800.1 |

PNG 导出没有变快，整体作者内存也没有下降。本轮不把约 4.5 GiB 的 RSS 观察合计包装成已解决的大卡内存问题。延迟初始化主要改善可取消性与一次性解码阻塞；JSON/PNG 包体并没有因此明显缩小。

原始 [改进前](large-before.json)、[改进后阶段构建](large-final.json) 和各 runner 保留 runtimeSha256。该阶段完成后还修正了偏好复制/预览降级、选择菜单及作者端恢复锁等收尾问题；最终构建的实际回归另见 native-final-target 与完整旧功能 runner，不把不同构建的一次测量称为最终精确性能保证。

主页面 PerformanceObserver 长任务、每个进程 PID/type/RSS、CDP renderer isolate JS 堆和时间戳均保留在原始 JSON。期望采样间隔 500 ms，导航/阻塞会形成间隙；最大采样值不是峰值。RSS 合计可能重复计算共享页，不等于独占物理内存，也不含 Node 测试驱动/服务器。DOM 出现不是逐帧光栅化测量，loadeddata 后还有真实 play/时间推进断言。退出后计数/音频/DOM 清理通过，不声称 GC 和整个 Helper RSS 立即回到基线。

## 相同固定夹具的独立受控对照

两项均为 29 MiB 合成 WAV、1 像素封面、同一页面；给 V8 old-space 384 MiB 限制不是限制整个进程内存，更不是手机。

| 观测 | 改进前 | 最终构建 |
| --- | ---: | ---: |
| 同步挂载 ms | 246.0 | 134.1 |
| 首次可播 ms | 274.6 | 440.0 |
| 16 ms 心跳最大观察间隙 ms | 264.1 | 151.5 |

[controlled-before.json](controlled-before.json) / [controlled-after.json](controlled-after.json) 的每个已跟踪资源退出均归零，实际音频进度大于 0。按需准备可能让首次可播稍慢，但减少一次性同步准备并能随角色退出取消。这里的前后单点堆值也不称峰值。

## 仍需验证

未做有损轻量导出、在线转码或改变原始音频。多 GiB 曲库备份、极多项目、OS 内存峰值与实体手机仍待专门验收。下一步优先测真实低内存设备、整条 Helper/PNG 字符串生命周期与可安全复用资源，不能只继续优化单个 atob 函数后宣称全链路稳定。
