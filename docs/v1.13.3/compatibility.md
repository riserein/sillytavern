# 跨浏览器与实体设备验收计划

已执行环境：Linux x64、Node 24、Playwright 1.56.1、实际 Chromium 154、SillyTavern 1.19.0；官方酒馆助手 4.11.3，以及单列的 4.9.5 选定回归。测试使用独立 dataRoot，不使用日常账号资料。

| 目标 | 本轮状态 | 需执行的验收 |
| --- | --- | --- |
| 桌面 Chromium | 见各 runner 的实际结果 | PNG/JSON、真实本地音频、备份恢复、账号切换、配额、角色生命周期 |
| Chromium 手机尺寸/触屏模拟 | 有独立随卡及制作页用例；属于模拟 | 不代替下面任何实体手机结论 |
| Windows/macOS 桌面 Chrome/Edge | 未实机验证 | 备份下载/选择、字体、原生导出、音频设备切换、休眠恢复 |
| Firefox 桌面 | 未验证 | ZIP 大 Blob 下载、IndexedDB 批事务、配额失败、BroadcastChannel、角色脚本停用 |
| Safari/macOS、WebKit | 未验证 | Blob/data URI、音频解码、字体加载、存储保留 API 缺失时提示 |
| 实体 iPhone/iOS Safari | 未验证 | 首次点击播放、后台/锁屏、内存压力、文件 App 选择 ZIP、清站点与配额、横竖屏 |
| 实体 Android/Chrome | 未验证 | ZIP 下载/恢复、后台/锁屏、系统回收、低内存、文件选择器、触屏拖动 |
| 真实远程音乐来源 | 独立探测受阻，未通过播放验收 | 站点内实际 audio 播放；分别测 CORS、重定向、过期、超时和格式，不只请求元数据 |

每个平台用全新测试账号与专用角色执行：导入本地 MP3/稳定合法直链，建立两个歌单和两个项目，添加封面、LRC、背景原图、自定义字体，调外观/音量/窗口，备份后在新设备恢复。对照每个文件 SHA-256、歌单顺序和角色重新映射，实际播放并看歌词同步。对损坏 ZIP、容量不足、服务器设置写入失败、中途关页，验证旧内容仍在、恢复记录能核对，不能靠清站点来“解决”。

随卡验收使用未安装音乐插件且已允许角色脚本的接收端：进入 A、同角色换聊天/开场白/AI 回复/重生成、快速 A/B 切换、立即退出、加载中退出、重复脚本、手动停用，再测试完整版接管。分别记录 DOM、音频、对象 URL、字体、监听器与任务清理；不要把计数归零当作整个浏览器内存立即回到基线。

大卡先逐级测试 5/15/接近 30 MiB；出现内存压力就记失败，不反复撞崩日常数据。记录系统/浏览器/Helper 版本、原资源 SHA、下载实际字节、时延及采样频率。单个堆快照和有限间隔最大采样值都不是内存峰值。当前高 RSS 的真实 Helper 链路不应直接拿来承诺低内存手机可用。

旧宿主若缺 `/api/users/me` 的稳定记录，完整版本地读写锁定，不能用显示名称猜账号。随卡缺官方 accountStorage 时偏好只在会话保留。没有 BroadcastChannel 的浏览器依靠重新聚焦和保存前核对，不能承诺后台跨标签即时通知；旧分发卡须重建重新导出才含新保护。
