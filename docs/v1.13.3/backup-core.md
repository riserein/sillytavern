# 阶段 C：二进制备份与恢复核心

本阶段增加内部模块和测试，播放器设置入口及旧库迁移在下一独立阶段启用。未把仅有模块/API 说成普通用户已能完成整条流程。

- 标准 ZIP STORE，目录版本 1；支持 ZIP64 归档计数/偏移，二进制资源独立条目，按真实 SHA-256 去重。单资源 128 MiB、JSON 目录 64 MiB、最多 100000 ZIP 条目；超限明确失败，不输出部分备份。常规 UI 本地单曲仍受原 100 MB 限制。ZIP64 尚不表示真实多 GiB 浏览器已验收。
- 音乐和草稿白名单，不导出整个酒馆设置/聊天/Cookie/凭据；已知 URL 认证参数移除并报告。原始音频字节不转码。远程音频仅元数据/URL。
- 读取尾目录、严格检查名称/重复/头信息/偏移/重叠/大小，再逐项校验 SHA-256 与 CRC；不解压未知压缩格式、不执行任何备份代码。
- 合并、仅补缺失、独立副本；真实字节重复音频识别；项目冲突新 ID 或显式跳过，容量超限拒绝，角色绑定须显式映射。
- 恢复先持久记录 → 资源单库事务 → 草稿单库事务 → 核对引用 → 宿主完整保存流程 → 服务器读回 → 最终核对。资源 ID/项目归属标记使回滚仅删除本次创建且未被修改/引用的内容。
- IDB 与服务器不是原子事务。发布后响应不明保留暂存；显式读回：等于 after 则确认，等于 before 则安全回滚，否则保留并提示人工核对。不会先清空原库。

核心代码 `data/backup.js`、`zip.js`、`checksum.js`、`restore.js`、`settings-commit.js`、`journal.js`；`local-store.js` 新增事务批量写入与不可与字符串歌曲 ID 冲突的复合键归属记录。账号命名空间 API 为后续准备，旧同步 API 的默认 legacy 模式保持兼容；生产启动入口将在账号归属 UI 准备后切换。

SHA-256 使用 MIT 的 @noble/hashes 1.8.0、约 5 KiB 固定浏览器模块；运行时无网络、无 WASM、无庞大 ZIP 依赖，HTTP LAN 也不要求 crypto.subtle。来源、锁定完整性和重建说明见 vendor/README.md。

测试见 backup-core-unit.txt：真实 Node SHA-256 对照、二进制回读、缺失/损坏/未知版本/路径、取消、去重/独立副本/容量、阶段失败及并发归属冲突回滚。这些内存 Store 测试不冒充真实 IDB 或酒馆验收；后续 data-browser.json 和真实账号专项分别记录。

回滚：本阶段没有修改旧数据库版本/名称，不自动迁移或清理；停用新增入口不影响旧库。已采用新账号库的数据应先通过新版本完整备份，不应直接降级后删除看不见的数据。
