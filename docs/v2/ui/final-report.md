# 2.0专项最终验证报告

本轮从 main `b69ee8d`（实际v1.13.3）续开发，阶段提交依次为 `aedef18`、`ae221d6`、`9270899`、`68a659f`、`fc64c7e`、`b868255`，最后补资源复用与回归。当前版本2.0.0-alpha.5，属于预发布。没有重写播放核心、改IDB版本、重置曲库、静默舍弃歌曲或生成离线安装包。

## 可使用的交付

- 同一音频核心上的收藏、独立收藏页、截止时间睡眠定时及可取消柔和过渡。
- 夜航兼容布局与玻璃、黑胶唱片机、磁带、极简四种布局；五种悬浮入口、静态图标检查/运输、移动输入区避让。
- 实际播放器实时设计器、窄屏三步、组件受限参数、撤销重做、随机配色/锁定/对比提示、设计字体、我的设计及安全JSON分享。
- 一个角色一套UI与歌单；PNG/JSON原生运输、官方Helper授权、接收端个人偏好隔离；原制作项目和共享界面独立JS/HTML/脚本JSON均保留。
- 完整ZIP运输模板、角色设计、图标及项目副本，旧音乐、字体、背景、角色数据和账号机制保留。

入口和操作见 [总说明](../README.md)、[设计器](editor.md)、[随卡导出](shared-export.md)。更新旧分发卡须制作端重新导出，不能远程修改接收者旧文件。

## 剩余边界与回滚

实体iPhone/Android、Firefox/WebKit、v2在Helper4.9.5的完整矩阵以及外部音乐平台真实联网未验证，见[专项验收计划](compatibility-plan.md)。系统完全挂起时无法保证睡眠回调准点；部分iOS不允许脚本调audio.volume。后台不必要视觉动画暂停，不借机改变音频或绕过手势权限。

大型卡仍涉及Base64、PNG元数据和JSON副本，内存压力没有彻底解决；多GiB备份、多标签及低内存实体机仍需专项测试。不同历史版本的所有已分发卡没有逐版真机重验；旧嵌入脚本不会被自动改写，旧项目流程和未知角色字段/脚本保护已有回归。

回滚前导出完整ZIP并保留分发卡。回退代码不清空或升级IDB，新字段旧代码会忽略；新版设计JSON请保留原件。要让接收端回退，制作端重建并重新导出。所有清理仍需用户确认且只删除已确认无引用资源，不操作其他账号或未知引用。

## 接近30MiB的真实酒馆大卡补测

large-native-runner.json / large-native-validation.json 使用当前构建、官方Helper及真实酒馆导出/导入，关闭Playwright trace以免把大文件追踪开销算进流程，另启用500ms内存采样；该选定用例通过。前一次未启用采样的运行也通过，分别保留，不假装第一轮已测内存。

此卡含28MiB原创WAV及所选字体、封面，内嵌资源31,283,226字节（约29.83MiB）。原始音频未改变。

## 发布前的字体时序补测

实际增加“延迟全局内置字体文件，刷新恢复专属宋体，然后释放字体请求”的操作，复现专属字体被晚到的全局游趣体覆盖（editor-late-font-initial-runner.json）。这属于已复现P2，位置 font-picker.js:57 的 apply、:65 的异步选择与 index.js:606 的字体选择回调。

修复让全局字体完成应用后重新应用当前设计的字体层；并在用户选择开始时记录角色作用域，异步完成后不把新角色的独立设计重置成默认字体。个人默认字体仍沿用原设置机制，不改原文件。editor-late-font-final-runner.json（含模板全部管理操作与有效/无效导入）、post-font-legacy-runner.json（5项）和 late-font-role-runner.json 记录刷新、旧字体及A/B加载中切换的专项回归。字体修复仅在完整版作者分支，随卡运行时SHA保持不变。

测试云环境的可复用启动说明已另存为配置草稿；草稿不表示环境已发布，需要在环境设置中保存/发布才用于新环境。这与已经实际运行的测试和GitHub提交分别记录。

字体A/B专项第一次在制作端重新进入已写入脚本的角色时，被官方Helper权限弹窗阻挡。补齐明确确认可信脚本的操作后通过，未用强制点击或更改Helper权限机制跳过授权。late-font-role-runner-initial.json保留该记录。最终另复查5项原字体回归，全部通过。

模板边界：JSON分享的是所选设计配置与自定义悬浮图标，背景图片及“沿用当前字体”继续继承安装端原有设置；不能把设计JSON当成包含全部背景/自定义字体/音乐的完整备份。完整ZIP和原生角色卡分发仍运输其各自规定的资源。
