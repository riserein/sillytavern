# 阶段六：角色独立设计与共享界面导出

## 常用的原生导出

在「播放器设计器」右栏选目标角色和已有歌单，保存绑定成功后，使用酒馆自己的导出按钮选择PNG或JSON。歌曲、歌词、所选UI、当前需要的悬浮图标、背景及选中字体随原有脚本运输。一个歌单可绑定多角色，各角色保留自己的布局和字体。PNG携带头像；JSON继续遵守酒馆原生格式，不声称其包含头像图片。

接收端不用安装音乐插件，需要官方酒馆助手并同意可信角色脚本运行。进入对应角色显示，同角色聊天/开场白/回复切换不重建音频；离开销毁。接收者收藏、音量、动画与无障碍只写个人偏好。作者允许后才能改布局，始终可以停止播放、禁用脚本。不会运输作者的全部设计列表，也没有恢复接收端字体切换。

## 制作页与独立文件

原有「角色卡播放器制作」继续保留原项目流程。要使用新设计，点击「读取当前设计器配置」，勾选「使用设计器布局与共享播放器界面」，然后检查资源并生成预览。

可下载独立JS、官方Helper脚本JSON、独立HTML预览、歌曲清单，并生成含播放器的角色卡JSON。没有发明新的Helper导入格式，复用现有type/script、content、enabled、button及export_with字段。该脚本的共享播放器与原生PNG/JSON使用同一构建，不依赖完整版插件/IndexedDB。HTML内可实际试听，但它不验证酒馆角色生命周期。

制作页中原有歌曲信息、排序、封面、歌词和本地音频编辑保留。当前设计以副本保存到制作草稿，图标实际字节也保留在项目资源中，完整ZIP一起备份。在共享模式下继续改制作页配色需要重新检查生成预览；原有旧模式的实时配色流程保持不变。需要更丰富的实时编辑请用设计器。自定义字体文件仍必须填授权说明，内置字体携带许可；接收端仅载入导出选中的一款。

## 容量与兼容

仍是单曲20 MiB、合计30 MiB资源、脚本45 MiB限制。图标另有1 MiB限制并计入合计，损坏图标不允许静态检查时悄悄丢掉。共享预览和导出都重新计算包含备用封面的实际总量。没有改原音频、原曲库或IDB格式，也没有静默删歌。

运行时包含四套布局的共享代码和CSS，尚未按单布局裁剪；三个原有备用封面仍会运输。只运输当前选择的配置/图标/字体，不运输全部模板或全部字体。实际构建体积及PNG/JSON测试文件大小见最终测试报告；不把一次堆采样称为内存峰值。

## 本阶段证据

- shared-unit.txt：166项Node通过，新增共享脚本记录格式/配置/图标运输、图标损坏拒绝和草稿离线图标保存。
- design-role-runner.json：先行角色专项通过。实际设计器分别把同一歌单绑定到A磁带/宋体、B极简/内置游趣字体，实际导出JSON和PNG；无音乐插件接收端A→B→A，布局和字体隔离，旧audio停止并清空，无重复播放器。
- shared-maker-runner.json：实际制作页读取当前设计、资源检查、共享iframe内实际试听，下载JS/HTML/脚本JSON及含音乐角色卡；干净Helper接收端重新导入后实际播放、离开清理，通过。
- 上述先行用例不是整个最终矩阵。完整8项原生与4项制作页结果由最终runner单独记录。

回滚前保留完整ZIP和角色卡文件。旧草稿默认保留旧播放器布局，新共享项目继续保留原歌曲与资源。需要退回旧版运行时请用制作端重新生成并重新分发，已收到的卡不会自动更新。实体设备、Firefox/WebKit和真实外部音乐服务并未由这些本地测试验证。
