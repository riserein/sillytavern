# 四种布局与共享 UI

在「外观 → 播放器形态」选择布局与视觉主题，音乐继续播放。夜航保持原有默认；旧字体、背景、配色字段都保留，选择「沿用当前配色」继续使用原配色设置。

| 布局 | 结构 |
| --- | --- |
| Crystal Glass | 竖向玻璃卡、大封面、下方歌曲信息和细进度条 |
| Vinyl Atelier | 黑胶唱片、封面唱片标签、唱臂、歌曲铭牌和刻度进度 |
| Cassette Memory | 横向双转轴磁带、歌曲标签与曲目编号、实体式按键 |
| Pure Form | 横向封面与控制区；可切换竖向和专注显示，细节由后续设计器编辑 |

不同布局共享曲库、收藏、歌词、队列、音量、定时器及过渡逻辑。配色会随原系统/手动日夜选择调整；自定义颜色保持作者明确选择。唱片和磁带轴只在实际播放时旋转，暂停保留角度；标签隐藏时暂停非必要视觉动画。动画关闭和系统减少动态效果不影响音频。

原生 PNG/JSON 已开始携带 uiDesign。原先分发的旧卡不自动升级，仍需制作端重建、重新导出。接收者不需要音乐插件，仍需官方酒馆助手授权。作者可以允许接收者修改布局；否则只提供动画和「显示全部控制与提示」等个人设置，收藏/音量等继续按原账号、角色、脚本隔离。

静态图标的格式、动画和像素尺寸检查模块已独立完成校验；本阶段尚未显示自定义图标导入和五种悬浮入口选择。完整设计器、模板管理及完整项目的主题导出继续在后续阶段接入，不把未完成界面当成可用功能。

- 160 项 Node 测试通过，见 layout-unit.txt。
- [layout-runner.json](layout-runner.json)：3 项通过，分别是静态图标解码前防护、受控页面中真实 MP3 的音频连续性、真实 ST 内四套布局。后者覆盖桌面及手机尺寸、每套歌词页/队列/播放失败及手动恢复，刷新保存及旧字体配色保留。
- [legacy-layout-runner.json](legacy-layout-runner.json)：旧夜航 6 项专项通过，包含拖动、配色、字体、系统日夜及复选框/滚动条。
- [layout-native-runner.json](layout-native-runner.json)：官方 Helper 4.11.3 的桌面黑胶及手机尺寸玻璃两项通过，实际 PNG/JSON 导出/导入、接收端音乐插件禁用、实际 MP3 播放与生命周期回归。它是选定测试，不是整个原生套件或四种布局全部 Helper 矩阵。

截图 `live-*-desktop.png`、`live-*-mobile.png` 来自真实 ST 浏览器；`controlled-*` 是受控开发页面，不能替代前者。`native/` 是真实无音乐插件的 Helper 接收端。手机均为 Chromium 视口/触屏模拟，没有实体 iPhone/Android、Firefox/WebKit 或真实外部音乐服务的新增验收结论。

## 代码与体积

`ui/config.js` 定义受限数据，`ui/presentation.js` 操作同一播放器 DOM，`ui/controls.js` 连接选择入口，`ui/layouts.css` 负责结构与视觉。CSS 入口 ui/player.css 先加载旧夜航，再加载新布局；随卡构建将两者直接合并，不依赖安装端文件。没有创建第二个长期音频实例，也没有通过暂停、重新选曲来切换 UI。

目前共享运行时代码和 CSS 含四套布局，尚未按单个布局裁剪代码。仅选择设计配置，不会把「我的设计」的所有模板装进卡；资源携带的进一步检查在图标和设计器阶段继续完善。脚本实际构建字节见 layout-build.txt，原 30 MiB 媒体资源限制保持不变；没有以大卡堆快照冒充内存峰值。

回滚前导出完整 ZIP，并保留已分发卡的副本；回退代码不会自动改已分发卡。旧音乐和 IndexedDB 格式未修改，新设计需使用能识别它们的版本恢复。
