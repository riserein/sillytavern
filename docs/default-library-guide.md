# 给开发者的默认曲库维护说明

普通安装者无需执行这里的命令。默认曲库由维护者随插件更新分发；目前你尚未选定歌曲，正式清单保持为空。

## 最省事的方式

把要加入的链接发给开发助手，并说明“替换默认曲库”还是“追加到原默认曲库”。直链还需要下面的信息。助手应先生成检查结果、验证播放，再提交 GitHub；不是让每个安装者自己操作。

| 你提供什么 | 还需要什么 | 当前能做什么 |
| --- | --- | --- |
| Openverse 单曲完整链接 | 核对作者、许可，实测音频 | 可自动取元数据；本次云环境访问被安全验证拦截，不能保证生成成功 |
| Audius 单曲/公开歌单完整链接 | 维护者先申请公开 API Key，普通用户不用申请 | 条件适配器读取曲目和歌单；本版本仍关闭，尚未完成真实播放验收 |
| 自己有权提供的公开音频直链 | 固定 ID、歌名、作者、永久链接和许可/授权信息 | 可以生成默认曲目，使用原有播放器播放 |
| 网易云、QQ、酷狗、酷我、咪咕、Spotify 等歌单链接 | 先落实获准的歌单读取服务 | 目前不能生成这些歌单的完整默认曲库，会报错并保留旧文件 |

分享网页不是音频直链。候选 Spotify/SoundCloud 官方播放器默认关闭：多来源产品的使用许可尚待确认；即使得到元数据，也不能把它写成“可直接完整播放”。

## 提供直链时，按这个格式发给助手

```text
操作：追加到默认曲库
固定 ID：rain-window（以后更新这首歌仍用这个 ID）
歌名：窗边雨声
作者：实际录音作者
音频：https://你的公开网站/music/rain.mp3
作品介绍：https://你的公开网站/music/rain
许可或授权名称：例如 CC BY 4.0，或作者授予的分发/播放授权
许可或授权证明链接：https://你的公开网站/music/permission
署名：作品名 — 作者 · 许可说明
确认：已获准让插件用户播放，地址长期公开，无到期签名
```

封面链接、专辑、时长（秒）可另行提供。许可证链接用于记录授权依据，不代表插件已经替你验证了版权；维护者仍需核实。音频不打包到仓库，也不从分享网站抽取。

## 自己更新时的步骤

电脑需安装 Node.js 20 或更新版，打开仓库目录的终端。生成器本身无需额外 npm 包。

1. 复制 [示例清单](../examples/default-library.json) 为你自己的 `default-library-input.json`。示例域名不能播放，两个确认值故意为 `false`，必须替换为真实信息并确认后才能生成。不要在清单中放账号、Cookie、私密 Key 或签名临时音频地址。
2. `sources` 中每项可以是歌曲/歌单分享链接字符串，或示例中的 `type: "audio"` 对象。支持一次混合多项；也可写 `{ "type": "share", "url": "完整分享链接" }`。公开直链要求 HTTPS 和常见音频扩展名，不接受带查询参数或片段的地址，避免误存临时签名；未带参数也不能由程序保证永不过期。
3. 先检查，不改正式清单：

   ```sh
   node scripts/update-builtin.mjs --input default-library-input.json --dry-run
   ```

4. 生成供检查的版本：

   ```sh
   node scripts/update-builtin.mjs --input default-library-input.json --out builtin-review.js
   ```

   **默认是完整替换**，适合使用一份长期维护的完整输入清单。只想追加时加 `--append`，原歌曲和新曲目按固定 ID 去重；已有 ID 保留原内容。要修改已有曲目，请更新完整输入清单并使用替换方式。直链还按相同 URL 去重。不同平台不按同名歌曲去重，避免混淆录音。
5. 检查歌名、作者、许可、数量和播放能力，并在测试酒馆试听。检查通过不等于真的能听到音频。
6. 写入正式清单：

   ```sh
   node scripts/update-builtin.mjs --input default-library-input.json
   ```

7. 提交 `builtin-tracks.js` 到 GitHub，更新插件版本。用户在酒馆里更新并刷新后看到新曲目，不需要离线安装包。

已有用法也保留：

```sh
node scripts/update-builtin.mjs --source "完整歌曲链接" --source "另一首或歌单链接" --name "默认曲库"
```

如果来源只能提供元数据或官方播放器，默认生成失败。只有明确接受这个限制时，维护者才可加 `--allow-metadata-only`；脚本会逐项提示，保存真实的 `external`/`embed` 能力，绝不改成完整播放。这个参数不会开启受限平台，也不能让无法读取的歌单突然可读，不能把纯来源书签变成正式曲目。

## 更新与失败保护

- 每次成功生成，正式版本号加一。先读取所有来源并校验，再用临时文件原子替换。任何来源失败、歌单未读全、超出 2000 首保护上限或直链信息无效，旧文件保留。
- `--dry-run` 不写文件；`--out` 仅写指定检查文件，版本基于仓库当前正式版本。
- 生成器不会保存 Openverse/Audius 的临时解析地址，只保留来源标识，播放时重新获取。明确由维护者确认的固定直链才保存 `url`。
- 默认曲库与用户总曲库、自建歌单分开。用户可隐藏默认库，也可复制歌曲到自己的歌单；默认库更新或移除不会覆盖已复制曲目、角色绑定或本地音频。
- 音频服务器文件失效后仍会播放失败。维护者负责更新链接、许可和可用性；不要把有期限的存储签名写成永久地址。
