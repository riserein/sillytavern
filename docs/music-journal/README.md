# 2.1 角色剧情配乐场景与私人音乐手账

交付版本 **2.1.0-alpha.1**，开发基线为 main `2d1f990`（2.0.0-alpha.8）。A—G 分阶段提交完成；最终测试、截图与限制见下方「阶段 G」。[操作说明](使用说明.md) · [数据与源码](数据与实现.md) · [验收汇总](results/acceptance-summary.json)

## 阶段 A：数据与兼容

已增加 `music-scenes.js`。账号设置中的 `roleScenes` 以角色 avatar 为绑定引用；`scenePreferences` 以相同角色引用保存个人选择。每个角色最多 12 个场景，每场景最多引用 200 个已有歌曲 ID，场景介绍 300 字，歌曲手记 500 字；文字按 Unicode 字符计数。音频仍只有原曲库中的一份，不存进场景对象。

每组包含 `version`、`avatar`、`defaultSceneId`、`scenes`、`notes`、`showNotes` 和 `keepCurrent`。场景保存名称、介绍、顺序、歌曲引用、封面／背景资源 ID、主题和是否随卡导出。数组顺序为永久排序。缺少歌曲的场景保留为草稿，不静默丢引用，也不当作可播放场景。没有有效场景时沿用原绑定歌单。

新增数据沿用既有账号设置持久化，不改 IndexedDB 结构。场景图片加入资源引用图，避免清理误删。完整 ZIP 包含场景、手记和个人选择；恢复预览列出这些角色，必须核对角色映射后恢复。复制模式重映射歌曲／场景 ID，冲突保留独立副本；超限拒绝写入。未完成草稿可备份恢复，仍标记为草稿。

阶段 A 验证：187 项 Node 测试及语法／数据检查通过。包括旧歌单兼容、角色隔离、个人选择优先、Unicode 上限、缺失引用、资源引用保护、ZIP 实际生成／读取及恢复 ID 映射。日志见 [results/stage-a-unit.log](results/stage-a-unit.log) 与 [检查记录](results/stage-a-check.log)。此阶段尚未声称通过浏览器场景切换或随卡验收。

后续依次实现 B 场景管理，C—D 手账与手记，E 设计器，F 随卡导出，G 完整浏览器与真实酒馆验收。

## 阶段 B：管理与切换

新增曲库中的「角色音乐场景」和播放页的「场景」入口。支持独立草稿、新建／复制／删除、介绍、默认场景、排序、选歌、图片、主题和预览；保存前不改正式场景。封面／背景先在内存暂存，写入失败不覆盖原配置；场景图片压缩为展示图，背景原文件保留。并发修改会拒绝覆盖，保存期间禁用编辑。

场景队列复用现有单 Audio 和可取消音量过渡。共用歌曲可保持来源与进度；暂停切换保持暂停；角色选择互相隔离；初次作者默认不会冒充玩家个人选择。未完成场景在选择器中标记为草稿。

阶段 B：187 项 Node 测试、代码检查、4 项 Chromium 浏览器用例通过，含手机尺寸的真实 `tap` 操作、配额失败注入、重新初始化恢复、快速切换、隐藏和清理。这里只是受控页面；真实酒馆与干净接收端仍待 F—G。

## 阶段 C：实际手账布局

新增 `journal` 布局，桌面使用同一册双页，手机以明确按钮翻阅音乐、歌词、手记和目录。封面、控制和歌词 DOM 被移动到书页，而非复制；不创建第二个 Audio 或第二个歌词解析器。返回旧布局时恢复原 DOM 位置。手机栏目通过实际触屏 `tap` 验证。

187 项 Node 测试及代码检查、6 项浏览器用例通过。覆盖同音频连续播放、原歌词 DOM 身份、三种歌词模式、目录实际切歌、旧布局恢复、双页几何和单页触屏。书页／目录截图在 `journal/`；此阶段尚未加入四套手账纸张主题。

## 阶段 D：歌曲手记

在场景管理的每首已选歌曲下展开「歌曲手记」，编辑最多 500 字的纯文本；同角色共用歌曲沿用同一份手记，不同角色独立。可关闭展示而不删除内容。场景介绍与歌曲手记分区显示，空内容自然留白，不绘制提示大框。专辑信息如有也保留并展示。

阶段 D：187 项 Node 测试、代码检查及 8 项浏览器用例通过。实际输入 HTML 形状的文字仍作为文本显示，没有生成图片节点或执行事件；切歌后手记立即对应新歌，隐藏手记不删除原内容。编辑截图见 `notes/`。

## 阶段 E：主题与设计器

四套双模式主题：复古羊皮纸、冷灰档案、午夜手账、现代极简杂志。沿用现有背景／文字颜色、字体与封面大小编辑，并增加纹理、书页边缘、装订线、双页比例、标题字重、留白、翻页和默认右页。减少动态效果时不播放翻页动画。设计 JSON 校验这些字段的类型与范围。

设计器可以联合预览当前角色的场景，仍使用原音频实例；关闭后恢复保存的场景与设计，不写入个人场景选择。撤销重做沿用既有设计历史。阅读提示检查整体遮罩后的颜色边界，不宣称对图片所有像素进行了扫描。

188 项 Node 测试、代码检查及 12 项浏览器用例通过。四主题 × 深浅 × 三材质 × 有无图片 × 两尺寸共 96 个场景，通过普通文字无框及 4.5:1 最低对比度检查。主题截图见 `themes/`，原始结果见 `results/journal-colors-*.json`。手机是 Chromium 触屏模拟，不代表实体设备。

## 阶段 F：共享随卡与项目资源

原生 PNG/JSON 桥、制作页独立 JS／Helper JSON／HTML 共用新场景数据。只导出勾选的完整场景；作者默认必须在选中集合内。按歌曲 ID 求有序并集，同一歌曲被多个场景引用只编码一份。未勾选场景的独有歌曲与手记不会分发；选中的草稿、缺图或容量超限会阻止整个导出，旧角色数据保留。没有场景的旧歌单沿用原逻辑。仅配置音乐场景、未绑定旧歌单的角色也支持原生导出。

接收端复用现有共享播放器、单 Audio 和角色清理机制。图片延迟解码，个人场景选择保存在原账号／角色／脚本偏好命名空间。作者端不会把个人选择写进角色卡。导出复用缓存同时区分场景配置，避免共享歌单的不同角色串用内容。

制作页新增「管理角色音乐场景」「读取当前角色场景」。读取是明确操作，保留项目已编辑歌曲并合并所需曲目，不自动覆盖已有项目。项目独立保存场景图片副本，整理源曲库后仍可恢复。ZIP 使用 SHA-256 文件去重并保存独立二进制，支持项目内的场景引用映射；存储扫描和恢复容量估算包含这些副本。

阶段 F：191 项 Node 测试与代码检查通过，12 项受控 Chromium 用例通过；共享构建不含完整版 IndexedDB／在线搜索／制作入口。模拟音频探测只用于 Node 导出校验测试，不作实际播放证据；真实音频解码及原生角色卡测试在阶段 G 单列。

## 阶段 G：最终验收（2.1.0-alpha.1）

A—G 已完成。完整代码随分阶段提交交付，未改原音乐库 IndexedDB 结构，也没有重新制作播放引擎。操作见 [中文使用说明](使用说明.md)，字段和源码分工见 [数据与实现](数据与实现.md)。原生随卡共享构建已重新生成；旧角色卡需由制作端主动重建并重新导出。

### 开发期间的问题与处理

- **浏览器复现并修复：** 场景弹层与原有弹层的 inert 状态不同步，选场景后手记等按钮无法点击。修复入口在 `index.js:2067` 与 `music-scenes-panel.js`；现在共用 `setSheetOpen`，加入选场景后继续操作的回归。
- **源码确认并加测试：** 仅被场景引用的默认曲库歌曲原本不会进入 ZIP 的来源清单，换空目录恢复会成为缺歌草稿。已在 `data/backup.js:102` 保留这些来源，并测试空目录恢复。
- **源码确认并加测试：** 既有 ZIP 项目白名单没有保留共享界面勾选和部分材质／配色字段。已补全 `data/backup.js:11`、`:12`，由 Node 和实际 IndexedDB 恢复验证。
- **保护性调整：** 原生按字体复用导出结果的缓存现在也区分场景集合（`card-player/native-export.js:557`）；全部取消场景不会擅自退回分发其他歌曲，缺资源阻止导出。源卡与原始曲库保留。
- **测试脚本错误：** 新测试最初误用 `store.dispose`、没有压缩超过既有图片上限的测试图，以及使用不唯一的按钮选择器；分别更正为原 API、真实制作路径和明确选择器，未放宽产品限制。
- **测试环境错误：** 并行 runner 共用 `test-results/native` 导致 trace 文件被另一轮清理。改用独立输出目录后重跑通过。旧回归仍保留 1 条该错误，不能据此声称产品首次全绿。

开发期失败日志在 `results/native-journal-*-failure.log`、`results/native-journal-oversized-fixture.log` 以及原始旧版回归记录中。已有 alpha.8 文字修复及历史验收资料未覆盖或改写。

### 未验证边界与回滚

- 手机使用 Chromium 的真实 `tap` 触屏模拟；没有实体 iPhone／Android，不等于 iOS Safari／Android Chrome 真机通过。Firefox、WebKit 和酒馆助手 4.9.5 本轮未重新验证。
- 嵌入 MP3 真实解码播放已验证；外部 HTTPS 音源是受控网络夹具，不是新的外网音乐平台可用性证明。
- 未测试 200 个角色均达到 12 场景的极限压力，或把本轮小型样本当作 30 MiB 内存峰值测试。
- 场景编辑器未保存的输入只留在当前内存；完整制作项目继续自动保存。删除引用歌曲后，场景保留缺失项待补齐。处理中退出的暂存图片可能保守保留，不自动删除不确定引用。
- 源码可按阶段提交回退，但旧版不认识新场景字段；先保留 2.1 ZIP，再回退。没有自动删除、重命名或迁移旧数据库。旧版随卡文件不会远程自动升级。
