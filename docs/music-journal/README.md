# 2.1 角色剧情配乐场景与私人音乐手账

开发基线：main `2d1f990`，2.0.0-alpha.8。按 A—G 独立提交，未完成部分不会当作已上线能力。

## 阶段 A：数据与兼容

已增加 `music-scenes.js`。账号设置中的 `roleScenes` 以角色 avatar 为绑定引用；`scenePreferences` 以相同角色引用保存个人选择。每个角色最多 12 个场景，每场景最多引用 200 个已有歌曲 ID，场景介绍 300 字，歌曲手记 500 字；文字按 Unicode 字符计数。音频仍只有原曲库中的一份，不存进场景对象。

每组包含 `version`、`avatar`、`defaultSceneId`、`scenes`、`notes`、`showNotes` 和 `keepCurrent`。场景保存名称、介绍、顺序、歌曲引用、封面／背景资源 ID、主题和是否随卡导出。数组顺序为永久排序。缺少歌曲的场景保留为草稿，不静默丢引用，也不当作可播放场景。没有有效场景时沿用原绑定歌单。

新增数据沿用既有账号设置持久化，不改 IndexedDB 结构。场景图片加入资源引用图，避免清理误删。完整 ZIP 包含场景、手记和个人选择；恢复预览列出这些角色，必须核对角色映射后恢复。复制模式重映射歌曲／场景 ID，冲突保留独立副本；超限拒绝写入。未完成草稿可备份恢复，仍标记为草稿。

阶段 A 验证：187 项 Node 测试及语法／数据检查通过。包括旧歌单兼容、角色隔离、个人选择优先、Unicode 上限、缺失引用、资源引用保护、ZIP 实际生成／读取及恢复 ID 映射。日志见 [results/stage-a-unit.log](results/stage-a-unit.log) 与 [检查记录](results/stage-a-check.log)。此阶段尚未声称通过浏览器场景切换或随卡验收。

后续依次实现 B 场景管理，C—D 手账与手记，E 设计器，F 随卡导出，G 完整浏览器与真实酒馆验收。

## 阶段 B：管理与切换

新增曲库中的「角色音乐场景」和播放页的「场景」入口。支持独立草稿、新建／复制／删除、介绍、默认场景、排序、选歌、图片、主题和预览；保存前不改正式场景。封面／背景先在内存暂存，写入失败不覆盖原配置；场景图片压缩为展示图，背景原文件保留。并发修改会拒绝覆盖，保存期间禁用编辑。

场景队列复用现有单 Audio 和可取消音量过渡。共用歌曲可保持来源与进度；暂停切换保持暂停；角色选择互相隔离；初次作者默认不会冒充玩家个人选择。未完成场景在选择器中标记为草稿。

阶段 B：187 项 Node 测试、代码检查、4 项 Chromium 浏览器用例通过，含手机尺寸的真实 `tap` 操作、配额失败注入、重新初始化恢复、快速切换、隐藏和清理。这里只是受控页面；真实酒馆与干净接收端仍待 F—G。

## 阶段 C：实际手账布局

新增 `journal` 布局，桌面使用同一册双页，手机以明确按钮翻阅音乐、歌词、手记和目录。封面、控制和歌词 DOM 被移动到书页，而非复制；不创建第二个 Audio 或第二个歌词解析器。返回旧布局时恢复原 DOM 位置。手机栏目通过实际触屏 `tap` 验证。

187 项 Node 测试及代码检查、6 项浏览器用例通过。覆盖同音频连续播放、原歌词 DOM 身份、三种歌词模式、目录实际切歌、旧布局恢复、双页几何和单页触屏。书页／目录截图在 `journal/`；此阶段尚未加入四套手账纸张主题。

## 阶段 D：歌曲手记

在场景管理的每首已选歌曲下展开「歌曲手记」，编辑最多 500 字的纯文本；同角色共用歌曲沿用同一份手记，不同角色独立。可关闭展示而不删除内容。场景介绍与歌曲手记分区显示，空内容自然留白，不绘制提示大框。专辑信息如有也保留并展示。

阶段 D：187 项 Node 测试、代码检查及 8 项浏览器用例通过。实际输入 HTML 形状的文字仍作为文本显示，没有生成图片节点或执行事件；切歌后手记立即对应新歌，隐藏手记不删除原内容。编辑截图见 `notes/`。
