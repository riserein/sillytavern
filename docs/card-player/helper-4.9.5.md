# 酒馆助手 4.9.5 接收端专项检查

用户提供的接收端版本为 4.9.5，且确认已启用角色脚本。本轮收到的是可视图片，没有可供工具读取的原始 PNG 附件，因此**未检查该用户角色卡的元数据，也未确诊它不显示播放器的原因**。

## 已完成的实际验证

- 官方酒馆助手 [4.9.5 标签](https://github.com/N0VI028/JS-Slash-Runner/tree/4.9.5)，提交 `af21bee2aadef5bf384f618e3456ff15ba9c431d`；使用标签附带的实际发布文件，不是替身 API。
- SillyTavern 1.19.0 + 桌面 Chromium，本项目当前 v1.13.1 运行时；播放器构建哈希见 [结果 JSON](native-helper-4.9.5-validation.json)。
- 制作端绑定并通过酒馆原生按钮导出 PNG / JSON；接收端禁用完整音乐插件、阻断其代码及资源、无完整版音乐数据库。
- PNG 重新导入后允许角色脚本，播放器出现，内嵌 MP3 实际解码且播放进度前进；离开角色后停止并清理资源。
- 作者换字体后重新导出 JSON，接收端导入后播放器出现并播放；分别验证携带的两款字体及禁止接收端换字体。
- 新分发文件检查入口能读取 PNG/JSON，拒绝没有随卡播放器记录的旧卡。

这是一项原生导出/字体/接收端播放用例通过，**不是 4.9.5 的全套生命周期、所有设备及旧版本卡片兼容性验收**。音频为本项目合成 MP3，不是外部音乐网站；未测真实手机或用户实际接收端。

## 首轮失败与重跑

[首轮记录](native-helper-4.9.5-initial.json)保留失败状态：PNG 显示、字体和播放已通过，随后 JSON 同名卡导入阶段，测试强制等待第二次授权弹窗超时。

官方 4.9.5 的 `src/store/scripts.ts` 和 `src/panel/script/use_check_enablement_popup.ts` 按角色名称记录授权/提示状态，而 4.11.3 使用头像 ID。先前已允许的同名卡再次导入时，4.9.5 不一定再次弹窗。

测试现要求出现实际授权弹窗或实际播放器，出现弹窗才点击确认；两者都没有仍失败，后续字体、音频进度和清理断言不变。修正此测试假设后，单用例重跑通过。没有修改播放器、替接收端开启授权或屏蔽错误。通过 `ST_HELPER_VERSION` 和 `ST_NATIVE_REPORT` 可选择助手版本与独立报告路径，默认 4.11.3 的报告不会被旧版专项覆盖。

## 对当前问题的结论

4.9.5 具备播放器使用的角色身份、脚本树及事件接口，本轮特定流程也实际通过；不能仅凭它的版本认定故障或要求升级。仍需取得用户实际发出的 PNG 原文件或同卡导出的 JSON，检查脚本标记、启用状态、音频及外观资源，再结合接收端错误定位。

图片预览不能代替读取原始 PNG 元数据；也不能从当前工具未拿到文件就推断原卡没有脚本或上传已损坏。请通过文件附件发送原导出文件，避免截图或另存预览图。
