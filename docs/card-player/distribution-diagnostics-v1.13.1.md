# v1.13.1 随卡播放器分发排错

本轮用户已确认接收端装有酒馆助手并启用了角色脚本。尚未收到实际分发的角色卡及接收端版本，**具体“不显示播放器”原因未确诊**，不能以缺少助手解释，也不能以测试通过宣布修复这份未知文件。

## 已确认的问题与修改

| 类型 | 位置 | 复现条件及影响 | 处理 |
| --- | --- | --- | --- |
| 已确认检查缺陷，中等 | `card-player/quality.js` 的 `verifyCardObject` | 播放器脚本或所在文件夹停用，旧检查仍可显示静态通过；不代表这种卡能运行 | 递归检查脚本及祖先启用状态并拒绝通过，不代替接收端授权 |
| 已确认诊断缺口，低 | `card-player/native-export.js` 的 `nativeCardScript` | 初始化同步抛错或异步拒绝时，旧入口仅留下控制台异常，接收端无法得知原因；不是已确认的初始化故障根因 | 新生成脚本显示版本和具体错误，提示可关闭；异常内容转义，不执行元数据 |
| 分发排错改进 | `card-player/handoff.js`、`index.js` 曲库入口 | 作者端本机播放正常不能证明发送的旧文件已经携带播放器 | 直接选择待发送 PNG/JSON，只读检查脚本、歌曲与资源；区分没有标记、脚本缺失/重复和停用，不改角色或数据库 |
| 未确诊用户实例 | 实际发送的文件及接收端 | 尚无文件和版本信息 | 等待原文件检查，不声称上述诊断已解决它 |

本机歌单绑定、卡内脚本存在、接收端允许运行和音频实际播放是独立状态。新增界面说明此区别。外链音频仍依赖原地址可访问；没有将外链伪装为内嵌音频。

## 验证

- 语法检查通过，102 个单元测试通过；启动错误用受控的同步/异步异常验证，只能证明报错处理。
- 实际 SillyTavern 1.19.0 + 官方酒馆助手 4.11.3 + Chromium：4 个不同浏览器用例在两次运行中最终通过。首轮 3 通过、1 个新增测试交互失败（未切到曲库页），修正后该用例重跑通过；未将其写成一次 4/4 全通过。
- 原生 PNG/JSON 导出并重新导入；接收端禁用完整音乐插件、阻断插件资源且不创建其数据库，播放原始合成 MP3；涵盖角色切换、同角色聊天连续性、脚本停用、错误资源及保存失败保护。
- 新入口实际读取导出的 PNG/JSON 通过，读取没有播放器的旧卡失败，接收端没有作者检查入口。
- 两次构建的原生运行时和共享 UI 字节哈希一致。
- 详细结果与实际体积见 [分发验证记录](distribution-validation-v1.13.1.json)。保留首次失败记录，不覆盖为成功。
- 手机用例是 Chromium 视口/触摸模拟；没有实体手机、Safari、Firefox 或用户接收端的验收。受控 HTTPS 合成音频不代表真实外部音乐站点播放通过。

## 使用方法

1. 更新插件并刷新酒馆，在曲库展开“随卡分发：接收端没有播放器？”。
2. 选择实际准备发送的 PNG/JSON。若没有随卡记录，打开已绑定的角色，检查/重建随卡播放器，再从酒馆原生菜单重新导出。
3. 将新文件导入没有完整版音乐插件的接收端，并允许酒馆助手运行该角色脚本。旧文件不会被插件更新远程替换。
4. 仍不出现时，提供该文件、酒馆/酒馆助手版本以及启动错误；新生成的 v1.13.1 脚本才有本轮可见报错。

没有更改歌库 IndexedDB 格式、歌曲、角色设定或现有主题；未关闭脚本授权开关，未自动执行未知文件，也没有新增离线安装包。
