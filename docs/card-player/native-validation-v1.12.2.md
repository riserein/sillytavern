# 1.12.2 原生 PNG / JSON 随卡播放器验收

> 历史报告：对应 1.12.2 发布时的字体和构建，不代表当前版本仍内置这些字体。

机器结果与构建 SHA-256 见 [native-validation-v1.12.2.json](native-validation-v1.12.2.json)。本报告针对「绑定歌单 → 酒馆原生导出 → 使用者直接导入」；1.11 单独制作页的结果不替代本项。

## 当前验收结果

- 本版原生随卡浏览器测试 **4 / 4 通过**，大字体用例扩展为体积、打包复用、固定字体及换字体后重新导出的验收。
- 本版单元测试 **85 / 85 通过**，语法检查通过。新增四项 PNG 保留字节/CRC、差异保护、酒馆 V3-in-chara 兼容及大元数据检查。
- 1.12.0 已通过的额外回归 **24 / 24**：完整版播放器选定的 20 项（含 B 布局、曲库、绑定、歌词、历史、主题、缩放、底栏与原存储）、旧角色脚本 3 项、旧制作页桌面完整流程 1 项。本次字体修复没有重跑这 24 项，也没有将其称为全量旧浏览器套件。
- 运行环境：SillyTavern **1.19.0**、官方酒馆助手 **4.11.3**、系统 Chromium。
- 手机项是 **375 × 844 触屏模拟**，没有声称已在实体手机或其他助手版本上验收。

## 实际执行的流程

作者端创建测试角色、通过原插件的导入页放入两首原创合成 MP3 和一首 HTTPS 直链测试音，建立 bill 歌单，设置背景、歌词、字体并绑定。正常保存绑定后，从 **ST 原生导出控件发送点击事件**，执行其真实保存、导出和浏览器下载流程，分别取得 PNG 与 JSON。没有用制作页输出替代原生导出。

原有桌面/手机流程在导出后删除作者的音乐 IndexedDB、关闭作者浏览器上下文。接收端使用全新浏览器上下文，禁用完整音乐插件，阻止其资源加载（仅允许酒馆用于扩展发现的 manifest），确认没有原音乐数据库。通过酒馆原生文件导入控件真实导入两种角色卡，接受酒馆助手的角色脚本确认，再实际点击播放。

大字体流程选择插件内的原始京华老宋体（33,259,644 字节），导入一首合成 MP3，保存绑定，从原生按钮分别导出 PNG 和 JSON。检查 JSON 确实携带 gzip 容器及原文件大小，PNG 下载大小小于服务器重复版本的 55%，绑定和两次导出合计只读取一次打包用字体。随后作者通过原字体选择界面换成破晓像素，重新导出 JSON。

接收端使用全新、禁用音乐插件的浏览器上下文，从原生文件选择控件导入京华老宋 PNG，实际启用助手脚本、加载字体、解码播放音频，退出角色后检查资源归零。随后导入作者换字体后生成的 JSON，确认只加载破晓像素、没有字体选择/导入入口并能播放。大字体 JSON 的本项证据为实际导出及内容检查，未单独声称完成其大字体接收端回读；普通字体 JSON 的接收端流程另有实际测试。

浏览器中恢复的字体与仓库原始字体 SHA-256 均为 `f7fef9fc413e9e2343f0bb432c51cca41c44b8fe37f071dc86b050896ae9f9e2`。字体未经格式转换、子集裁剪或改名；压缩容器约 21 MB，仍计入 30 MB 的资源总容量。

本次测试卡含完整京华老宋及一首合成 MP3，实测大小如下（MB 按十进制显示；不是用户实际卡片的测量）：

| 文件 | 字节 | 约 MB |
| --- | ---: | ---: |
| 酒馆服务器生成的重复 PNG | 82,084,277 | 82.08 |
| 精简后实际下载的 PNG | 41,080,448 | 41.08 |
| 实际下载的 JSON | 30,753,975 | 30.75 |

PNG 减少约 **49.95%**；JSON 未承诺体积下降。机器结果同时记录了自动化过程中的导出等待时间，包含 Playwright 跟踪、页面保存及测试环境开销，没有无跟踪的旧版/新版速度对照，因此不把它宣传为固定倍数提速。缓存的证据是绑定及两次导出共一次字体资源读取。完整字体不改为联网下载。

| 项目 | 结果及证据 |
| --- | --- |
| 原生 PNG、JSON 均携带播放器 | 两种文件分别在桌面及手机尺寸重新导入并播放 |
| 现有界面复用 | 从同一份 index.js、组件与 CSS 编译；黑胶球及展开界面保持原有类和样式，音乐导入页与入口不存在 |
| 音频、图片与字体独立 | 本地 MP3 实际解码且进度前进；背景与封面可读；已携带字体在接收端真实加载 |
| 大字体随卡 | 京华老宋实际绑定及两格式导出；PNG 接收端字体加载、字节哈希、播放与退出清理通过 |
| 固定所选字体 | 作者从京华老宋切到破晓像素重新导出；接收端分别实际加载对应字体，所有随卡实例没有字体切换或导入控件 |
| PNG 瘦身 | 对服务器实际输出与下载文件测量；两份角色数据核对一致后保留标准 V2 PNG，真实重新导入及播放通过；JSON 不宣称同样缩小 |
| 播放控制 | 真实切换三首歌、调整音量、跳转进度，歌词切换与窗口缩放可用 |
| 同角色持续播放 | 开场白、AI 回复切换、编辑、重新生成、不同聊天文件都保持原 audio 身份与播放进度 |
| 历史 | 真实 playing 事件后出现三首最近播放；离开并返回角色仍保留记录 |
| 离开和返回 | 离开后音频暂停并清空 src，DOM 移除；监听、订阅、定时器、观察器、对象 URL、字体、内存资源计数归零；返回重新出现 |
| 重新导出最新内容 | 绑定后修改歌名，原生导出包含修改后的歌曲信息 |
| 保留角色内容 | 角色设定、其他扩展、助手变量、其他作者脚本与数据保留 |
| 尊重助手导出选项 | 其他脚本显式关闭随卡数据/按钮时，导出副本清空这些字段；作者端内存与实际卡文件保留原数据 |
| 失败保护 | 本地音频缺失或模拟酒馆保存 500 时拒绝导出，保留此前完整脚本；取消绑定仅移除本工具的脚本 |
| 旧绑定 | 没有随卡脚本的旧式本地绑定，在首次原生导出时自动生成 |
| 准备期间切换角色 | 在运行文件加载期间切到另一角色，不向另一角色的脚本库写入播放器 |

音乐使用本项目生成的合成 MP3，实际由 Chromium 解码播放。HTTPS 直链由测试网络路由提供同一音频，用于验证地址保留与浏览器播放通路，**不代表外部商业音乐平台已验证可播放**。本环境对 Wikimedia 的真实 HTTPS 请求收到代理 403，因此没有把外部音源长期可访问性写成通过。重新生成使用 ST 的真实 Generate 路径，LLM 回包和分词接口使用固定测试响应，不需要调用付费模型。

## 代码范围

- `card-player/native-export.js`：绑定时随卡保存、原生导出前刷新、资源检查、助手数据同步与失败回滚。
- `index.js`：复用入口、可注入独立存储/上下文、移除音乐导入入口、显式释放资源；原插件保留自己的数据库与设置。
- `card-player/native-entry.js`、`shared-environment.js`：独立角色上下文、内嵌资源、角色命名空间与宿主资源归属。
- `card-player/font-transport.js`：大字体无损传输与限量还原，取消/损坏处理；保留小字体原有传输方式。
- `card-player/png-size.js`：比对两个角色数据块，仅清除完全重复内容；处理旧块包含 V3 标识的酒馆输出，保留完整字段并重算 CRC。
- `card-player/entry.js`：共享已经实测的酒馆助手角色身份与生命周期适配。
- `scripts/build-native-player.mjs`：编译相同界面，移除完整插件数据库、平台搜索和制作器运行依赖；发布产物已提交，安装者不需要构建。
- `font-picker.js` 仍用于完整插件；独立版直接加载固定字体，移除选择器。`resizing.js`、`night-ui.css` 继续支持宿主视口与五个导航项；完整插件仍为六页。

## 重现

在隔离的 ST 测试资料目录安装官方酒馆助手与本仓库扩展，启动 ST，然后运行：

```sh
npm ci
npm run build:card-native
npm test
npm run check
CHROMIUM_PATH=/usr/bin/chromium npm run test:card-native
```

云环境如果默认 npm 缓存目录不可写，先设 `export npm_config_cache=/tmp/stm-ui-build-cache`。必须确认构建成功后再测试；本次最终结果的 SHA-256 已核对与发布构建一致。

测试只创建和删除 `RSCP_Test_` 前缀的自有卡片。每项接收端都使用独立浏览器上下文，避免作者缓存掩盖资源缺失。

使用和容量限制见[中文说明](export-guide.md)。不改变 IndexedDB 格式，不加入未经授权的商业音乐，不绕过酒馆助手脚本启用确认。
