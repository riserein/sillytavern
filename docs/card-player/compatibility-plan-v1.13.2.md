# v1.13.2 跨浏览器与真机补充验收

这是待执行设备的验收计划，不是全部通过的声明。基础操作沿用 [v1.13.0 计划](compatibility-plan-v1.13.0.md)，本轮实际结果见 [审计报告](../quality-audit-v1.13.2.md)。

| 环境 | 当前证据 |
| --- | --- |
| Linux Chromium 154 + ST 1.19.0 + 官方 Helper 4.11.3 | 当前真实酒馆及受控专项报告 |
| Linux Chromium + 官方 Helper 4.9.5 | 单项 PNG/JSON/固定字体/内嵌音频专项，范围见独立报告 |
| Chromium 手机视口与触摸模拟 | 已测；不是实体手机 |
| Windows/macOS Chrome、Edge | 未在这些 OS 实测 |
| Firefox、macOS Safari、Playwright WebKit | 本环境未执行；WebKit 通过也不能代替 Safari |
| 实体 iPhone/iOS Safari、实体 Android/Chrome | 未执行；需要实际设备 |

每台设备记录 OS、浏览器、ST、Helper、可用空间、文件大小、音频编码和网络环境。测试使用有权分发的文件；先备份并使用专用资料，避免对日常音乐库做配额/存储清除实验。

1. 分别导出小卡和近 30 MiB 资源卡，JSON/PNG 各一；接收端禁用完整版、移除作者音乐数据库。检查字体/歌词/角色字段/其他脚本保留，实际按播放、观察进度和声音。
2. 对 20 MiB 音频、28 MiB 混合音频与图片、较大像素图片分别记录导入、首播、下一首、重复打开、导出重导入耗时与内存；不要只看文件字节或模拟器。内存不足时不得覆盖旧卡/旧草稿。
3. A/B 反复切换十轮、同角色切聊天/开场白/回复/重新生成、停用/重启脚本、字体加载时退出；确认音频停止、实例唯一、对象 URL/监听/定时器归零。后台、锁屏、旋转、BFCache 返回另测，并区分系统策略与实际缺陷。
4. 在专用服务器人为令设置保存 500、200 错误 JSON、断网；更换封面后刷新，确认旧资源未丢。正常恢复保存后，确认当前资源可用且旧引用安全回收。
5. 在浏览器实际存储配额不足时导入音频/字体/草稿，确认明确失败且旧数据保留。不要把改写 `navigator.storage.estimate()` 或模拟抛错说成真的 QuotaExceededError。
6. 导入他人携带播放器的卡；保存自己的另一张卡的绑定并转发外来卡，核对外来脚本不被删除。明确解绑自己的卡则只移除自己管理的播放器。
7. 同源切换 ST 测试账号，检查草稿/音频可见范围；跨账号是否泄漏尚未验收，不能仅凭单账号套件结论决定隔离策略。
8. 同时安装完整版，确认只显示一个播放器、接管后无旧音频。外来随卡音乐不会自动合并为本机曲库，应记录这一现有策略，不能误判为数据已导入。
9. 用独立真实 HTTPS 音频及歌词服务验证加载、重定向、断网/失效重试、混合内容与格式。不要使用路由替身得出外网成功结论，不得关闭 TLS 验证。
10. 通过第三方角色编辑器保存再导入，对照原文件核对扩展和脚本。编辑器去除扩展、不同 V2/V3 元数据冲突与插件失败应分别记录。

跨设备完整曲库/草稿恢复目前没有实现，不能作为已通过项。未来加入备份后，需要补全断电/部分写入/容量不足/重名 ID/角色映射/旧格式兼容及失败回滚验收。
