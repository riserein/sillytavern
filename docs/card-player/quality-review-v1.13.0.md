## 已实现的 A—E

- **A 容量分析**：制作页逐首音频、封面、歌词、背景与选中字体大小；脚本实际序列化大小；JSON/PNG 的播放器部分估算；原生额外封面计入 30 MiB；超限给出资源名与压缩/换源建议。歌曲绝不静默删除。外链标记为不内嵌、远程体积未验证。估算不是整个角色卡文件的精确体积，导出后以实际字节为准。
- **B 项目草稿**：约 400 ms 防抖自动保存；关闭前排队保存；重新打开/刷新恢复；多项目切换、复制、删除。Blob 原始字节保存在新库 `riserein-card-player-projects`，不升级或改写 `riserein-sillytavern-music`。资源与草稿快照一笔事务提交；原音乐库删除不会清理草稿内的副本。
- **C 完整性**：导出前检查资源/容量；导出后从 PNG/JSON 重新读取，以完整脚本字节核对全部音乐、歌词、封面、背景、字体和 UI，另核对角色 V2/V3 标准数据及 extensions。制作页可手动核对已导出文件。分开显示静态结构、浏览器解码与真实酒馆验收；不是播放认证或数字签名。没有原制作副本时，手动核对只能证明结构自洽，不能证明文件未被其他人篡改。
- **D 生命周期**：待初始化单实例、停止晚到的读取、退出清理、脚本命名空间隔离、完整版接管和专项回归。一个页面仍只显示一个本项目播放器；两个同角色脚本不会同时播音，后挂载者接替并清理旧实例，偏好按脚本隔离。
- **E 维护更新**：版本记录写入随卡标记、配置和播放器外观说明；“检查 / 重建当前角色的随卡播放器”入口保留歌单与 UI，重新生成当前版脚本。旧卡不会被远程升级；制作端重建后必须重新导出并分发。

## 歌词调查与修复

只静态查看用户提供的 `10.11Oswin.json` 中“播放器悬浮球”的结构，没有执行它，也没有复制其中歌曲、图片、UI 或专有实现。其歌词来自联网搜索、直带歌词地址及本地缓存，组合了 Meting、LRCLIB、Lyrics.ovh 等来源；音频 URL 自身并不天然包含歌词。

原插件已有 USLT 内嵌歌词读取、LRC/TXT、同步显示和随卡运输，缺少联网匹配入口；制作页直接添加文件又没有调用同一元数据读取器。新增 [lyrics.js](../../lyrics.js) 使用 **LRCLIB 官方只读 API**，用户主动搜索、选择、预览并确认后保存；同名、翻唱、现场录音不自动覆盖。不接入未经验证的 Meting 公共音频端点，不以取得歌词冒充取得歌曲播放权限。

接口参数与字段依据 [LRCLIB 官方源码](https://github.com/tranxuanthang/lrclib/tree/04369d3f7c6e8cba1790629f26f866547a9b8f88/server/src/routes/search_lyrics.rs) 及其 router 的 CORS 配置核查。服务本机访问被代理以 CONNECT 403 拒绝；联网匹配效果未通过真实网络验收，不能保证每首歌有词。受控响应测试和真实 MP3 标签解码测试通过仅代表插件链路正确。确认后的歌词以文字保存，接收端无需联网查词；来源地址随歌曲保留。

## 真实外网结果

本轮真实外网探针没有伪造通过：MDN CC0 音频请求报 `ERR_TUNNEL_CONNECTION_FAILED`；Openverse 报 `ERR_CERT_AUTHORITY_INVALID`，未关闭证书校验；LRCLIB 的 curl 请求报代理 CONNECT 403。Audius 缺维护者公开 Key，正式适配器继续关闭。详见 [公开音频](public-audio-validation.json)、[在线来源](online-live-v1.13.0.json)、[歌词网络](lyrics-network-validation.json)。

因此能确认的是本机内嵌合成 MP3 的真实解码/播放，以及受控 HTTPS 音频响应接入播放器的闭环。外部在线音乐和在线查词必须在可访问对应服务的使用者网络中再验收，不能称为本轮真实成功。

## 本轮测试过程中的修正

完整版批量回归首次为 58 通过、1 个新增用例失败：搜索界面与隐藏制作页存在同名测试定位，修正为限定歌曲详情范围；随后的新用例重载又需要先等待酒馆的真实延迟保存响应。补充该等待后已单独通过，原始失败报告保留，不将它改写成一次性全绿。

原生导出新增配置快照检测曾把角色切换自动分配的默认封面当作作者编辑，造成误阻止导出；已将播放游标和自动封面缓存从变更检测中排除。保留在资源读取期间主动改歌名时阻止导出的断言，既检查数据一致性，也避免角色导航误报。

## 尚未验证或明确限制

- 字幕标签自动读取当前以 MP3 的 ID3/USLT 为主，未实现 FLAC/Vorbis、M4A 内嵌歌词及所有 SYLT 变体；LRC/TXT 请使用 UTF-8。
- 手动 PNG 复查读取标准 `chara` / `ccv3` 的 `tEXt` 元数据；不将第三方特殊 iTXt/zTXt 写法、压缩元数据或冲突副本认定为已兼容。安全读取上限 160 MiB，制作页 JSON 输入/输出上限 60 MiB。
- 本轮浏览器预检状态针对音频加载/解码；图片及字体仍需预览实际显示。静态资源相同不等于浏览器能解码所有格式。
- FontFace/ImageBitmap 的底层解码并非所有浏览器都提供取消接口；退出后禁止应用迟到结果，并关闭后来返回的位图。实体设备上的解码开销和系统后台限制仍需人工验收。
- 多个独立作者页面同时改同一卡的服务器保存没有跨客户端事务锁；本机操作顺序、单页面导出队列与草稿版本冲突检查不能冒充全局协同编辑锁。

本次实际变更文件还包括 `background.js`（关闭裁剪器与晚到位图）、`card-player/config.js` / `core.js`（保留歌词来源）、`lyrics.js`、两个构建后的独立运行时及共享 UI 产物、相关测试配置/脚本、版本声明与中文文档。未新增运行时第三方包，未改原音乐 IndexedDB 版本，未打包参考角色卡资源，也未新增付费服务或后端。

独立制作页的旧缺失音频用例已更新为两步：原曲库文件删除后，已有草稿必须仍可导出；再从缺失源建立新项目，才应提示缺失并阻止导出。这里没有删除错误断言，而是将它应用到真正没有资源副本的用户操作。

最终构建核对发现独立运行时代码变更也改变了原生压缩包的变量命名，已重新生成原生包并对最终哈希重跑真实酒馆套件；连续两次同源码构建的五个产物逐字节一致。报告只引用最终包的验收哈希。
