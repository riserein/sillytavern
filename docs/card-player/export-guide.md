# 把绑定歌单随角色卡发给朋友（1.12.2）

## 作者怎么做

1. 更新本音乐插件并刷新酒馆。
2. 在「导入」添加本地音乐文件或稳定公开 HTTPS 音频直链。
3. 新建歌单，例如 **bill**，把要分享的歌曲放进去；设好封面、歌词和外观。
4. 打开 bill 的「管理此歌单 → 绑定角色」，勾选 **Amber**，点击「保存绑定」。
5. 等到「音乐已随卡保存」。现在直接用**酒馆自带的角色导出按钮**选择 **PNG 或 JSON**。
6. 把导出的正常角色卡发给朋友，不需要另发 MP3 或安装包。

不需要进入单独的播放器制作页，也不需要先生成另一张“含音乐卡”。旧版已经绑定的歌单，在更新后重新保存一次绑定，或直接从酒馆原生按钮导出，都会触发随卡准备。

保存绑定时会写入角色卡；每次原生导出前，再读取最新的绑定歌单、歌曲和外观重新生成，避免导出过时副本。歌曲文件缺失、音频无法加载、受限平台来源或容量超限时，会说明原因并阻止这次导出。旧卡文件不会被清空，插件本机的绑定与曲库也保留。请解决提示后重试，不要把之前生成的旧文件当作此次更新。

移除绑定后，下一次保存绑定或原生导出会删除本工具标记的自动随卡脚本；不删除其他作者的脚本。如果把 bill 同时绑定多个角色，保存绑定会分别写入这些角色卡。

## 朋友怎么用

1. 使用 SillyTavern，安装并启用**酒馆助手**。
2. 正常导入收到的 PNG 或 JSON 角色卡。
3. 进入角色时，如酒馆助手询问是否启用角色脚本，查看来源后启用。助手的安全确认不能由音乐插件绕过。
4. 出现播放器后，手动点播放。浏览器可能需要首次点击才允许出声。

朋友**不需要安装本音乐插件**。酒馆助手是运行角色脚本所必需的环境；只有普通酒馆、完全没有脚本运行器时，角色卡数据不能自行执行 JavaScript。

接收端复用本项目现有播放器的 HTML、组件和 CSS，显示相同的黑胶浮球与展开界面。保留播放、曲库、最近播放、排行、外观、歌词、队列、迷你播放条、拖动与缩放；移除整页音乐导入和制作人入口。**仅导出作者当时选中的一款字体及其许可，接收端没有字体切换或字体导入功能。** 完整插件仍可选择所有已安装字体；作者换字体后重新导出，新的卡使用新的选择，已经发出的旧文件不变。

同角色内聊天、切换开场白、切换回复、编辑消息和切换聊天文件不重新初始化音频。离开角色、回主页、停用脚本或其 iframe 被移除时停止音乐并清理资源。返回角色重新出现，仍需手动播放。音量、主题、位置和历史按角色及播放器项目隔离保存，不使用作者的原曲库数据库。

## 歌曲、图片和字体怎么携带

- **本地歌曲**：读取完整音频字节嵌入角色脚本。发出后即使删除作者电脑的文件或浏览器曲库，已发出的卡仍含音频。
- **音频直链**：保留稳定公开 HTTPS 地址。朋友播放时由其浏览器向原音源加载；原网站删除文件、改权限或失效后，直链仍会失效。导出时通过检查不保证网站永远在线。
- **封面、歌词、背景**：随脚本携带，不依赖作者电脑的 blob URL、IndexedDB 或完整插件的资源路径。
- **字体**：选中的内置字体及对应许可随卡携带。超过 20 MB 的内置字体自动采用无损压缩容器，朋友打开卡片时还原原始文件；不转字体格式、不裁剪字形、不修改名称。京华老宋约 32 MB 的原文件可按此方式携带，恢复后的 SHA-256 与原始发布记录一致。自定义字体仍需可核实的分发授权记录。
- **平台分享页**：网易云、QQ、Spotify 等页面地址不能充当音频直链；需要动态解析或访问授权的音源不自动打包。

容量：单首内嵌音频最多 20 MB；原生随卡字体的原文件最多 64 MB，大字体按压缩后的字节计入打包资源，歌曲/封面/背景/字体打包合计最多 30 MB、最终脚本最多 45 MB。京华老宋压缩包约 21 MB，会占用相应容量。PNG/JSON 都会因内嵌歌曲而变大。超限时减少曲目，或将部分音乐换成自己有权使用且长期可访问的音频直链。不会静默丢歌。旧版单独制作页仍沿用其 20 MB 字体限制，本次修复针对“绑定后原生导出”。

如果接收端浏览器不支持解压，或字体包损坏，会使用设备字体并提示原因，音乐仍可播放。解压期间离开角色会取消加载，不会在离开后再弹出播放器。

PNG 使用酒馆自身的导出逻辑，因此正常携带头像与角色数据；JSON 使用酒馆自身的 JSON 格式，不额外加入头像图片。其他角色设定、世界书、扩展和脚本保留。

## 文件大小和导出速度

没有将全部内置字体装入一张卡。京华老宋原文件约 32 MB，无损打包后仍约 21 MB，转换为角色脚本里的文本后还会增加体积；固定字体并不意味着能将完整字库缩成几 KB。本项目保留原文件，不裁剪字形或修改字体。

部分酒馆版本的 PNG 同时写入 `chara` 和 `ccv3` 两份相同角色数据，音乐与字体也重复一次。本插件只在核对两份内容完全相同（除格式标识）后，将下载文件精简为**标准 V2 PNG**，保留完整角色信息、原头像、歌曲和字体。若两份数据不同，保留原文件，不冒险删数据。该优化针对发出的文件；酒馆自己的内部存储仍由酒馆管理。JSON 不存在这层重复，不承诺同样减半。

同一页面内，未更换的内置字体只打包一次，内置封面也会复用。每次导出仍检查当前歌曲、用户资源和直链；播放器内容相同则跳过本插件额外的整卡重写，修改歌名、外观或字体后会重新保存。首次导出和酒馆自身的保存仍需要时间。

## 原有制作页

「曲库 → 角色卡播放器制作」仍保留为高级工具，可编辑独立导出副本，生成脚本 JSON、JavaScript、预览 HTML 与歌曲清单。它是 1.11 的另一个工作流，不能代替上述原生导出验收；其独立主题预览与共享完整版界面的随卡播放器分别验证。详见[历史制作页说明](maker-guide-v1.11.md)。

## 测试和兼容性

开发入口：`npm run build:card-native` 编译共享界面，`npm run test:card-native` 在真实酒馆和官方酒馆助手环境运行。完整证据、外部网络限制与手机模拟边界见[原生导出验收](native-validation.md)。

助手不同版本、实体手机、第三方角色卡压缩或裁剪工具仍需在使用环境确认。会移除 `data.extensions.tavern_helper.scripts` 的工具会同时移除随卡播放器，发送时请用酒馆原生导出后的文件。
