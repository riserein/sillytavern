# v1.8.0 核查与 v1.9.0 阶段报告

核查日期：2026-10-15。起点为 `8dc6de0` / v1.8.0，继续修改现有前端扩展，未重做播放器。下面把代码、测试替身、真实接口、真实播放和平台使用条件分开。

## A：现有实现与缺口

已阅读根目录运行模块、`platforms/`、默认清单与脚本、README、CHANGELOG、在线调查及全部单元/浏览器测试。原有功能保留：本地批量导入、直链、共享歌单、角色绑定、LRC、历史与排行、窗口、外观、字体、封面及 IndexedDB。

| v1.8.0 模块 | 已实现 | 核查发现 |
| --- | --- | --- |
| `platforms/service.js`、`links.js` | 十一平台标准链接识别、能力注册、搜索隔离、预览 | 多数平台只有来源书签；没有商业搜索、完整歌单读取或账号播放，不能算在线播放 |
| `platforms/providers.js` | Openverse 搜索/详情/音源解析；条件 Audius 搜索/resolve/歌单/stream | v1.8.0 仅有替身验证；Audius 未配 Key。真实接口和流媒体必须另测 |
| `platforms/request.js` | 超时、取消、缓存和 429 冷却 | **发现缺陷**：`cacheMs: 0` 仍能命中旧缓存，导致所谓强制刷新无效；已修复 |
| `online-panel.js`、`library.js` | 搜索、完整预览、确认和容量检查 | **缺口**：超过 200 首只能拒绝，没有选择子集；原歌单作者/封面未保留。已补选择、原始总数和来源字段 |
| 默认库与生成器 | 版本化、隔离、自有副本、失败原子保护 | **缺口**：仅接收分享链接，不支持固定直链元数据/批量文件/追加/预检查。已补齐 |
| `index.js` | 原生播放器统一控制，真实 `playing` 才计历史 | **缺口**：音源刷新受缓存缺陷影响，平台播放错误过于笼统。已修复刷新，增加有界加载等待、实际播放检查和按浏览器错误分类提示 |
| 默认库详情 | 可浏览、编辑和复制 | **发现缺陷**：仅查看详情就复制到自有曲库并消耗容量。已改为只有编辑或加入歌单才保存副本 |

本轮还支持在重新导入得到完整元数据时升级原来源书签，保留曲目 ID、歌单关系、个人改名、封面和歌词；原有普通书签不会凭空变成可播。

## B：真实访问与播放验证

**本阶段“至少一个在线来源真实播放成功”的验收未通过。** 不以代码和 Mock 代替。

| 真实请求/操作 | 观察结果 | 能证明与不能证明 |
| --- | --- | --- |
| Openverse `/v1/audio/?q=piano...` 及 API 根目录 | HTTP 403，`cf-mitigated: challenge`，Cloudflare 验证页 | 已到达网站的安全验证层；未获得音频记录，不尝试绕过验证 |
| Audius `/v1/tracks/search?query=piano&limit=2` | 终端 HTTP 200，真实标题、ID、时长、权限字段 | 公开搜索端点当时可访问；不证明已接入生产应用或浏览器可播 |
| Audius 单曲 `/stream` | 测试中 HTTP 403 / `error code: 1010`，另一次转移请求被出口代理拦截 | 未取得可播放音频，不能断言 Key 可以解决此错误，也不能宣称匿名流播可用 |
| Audius `/v1/swagger.yaml` | HTTP 200，读取官方规范 | 搜索有 offset/limit；详情 `data` 是对象。歌单 tracks 路由当前规范未列 offset/limit，不能假设总会分页；实现同时接受一次完整返回，并通过声明总数校验与重复页保护，不静默截断 |
| SoundCloud 官方 `/oembed` | 终端 HTTP 200，真实曲名、作者、封面及官方 iframe 地址，响应含 `Access-Control-Allow-Origin: *` | 真实元数据可读；没有证明 iframe 在浏览器发声，更没有证明本产品符合使用条件 |
| Spotify 官方 `/oembed` | 终端 HTTP 200，真实标题/缩略图，响应含 `Access-Control-Allow-Origin: *` | 仅证明官方元数据响应，不证明全曲、账号或嵌入播放 |
| 云端真实酒馆中的 Chromium，不替换外部接口 | HTTPS 请求失败，记录到 `net::ERR_CERT_AUTHORITY_INVALID` | 浏览器没有信任云环境的出口代理 CA；尚不能现场验证 CORS、解码、重定向后音频和发声 |
| Meting 公共端点 | i-meto 403 验证页；injahow 对不存在的歌单 ID 返回 HTTP 200 / `unknown playlist id` | 证明 injahow 当时有响应，不能证明真实有效歌单全量可读、音频可播、CORS 或长期服务许可；未作为默认后端 |

尝试将云环境提供且有效的代理 CA 加入 Chromium NSS 信任库，被自动审批拒绝，理由是持久扩大 HTTPS 信任范围，需要明确授权。没有修改信任库，也没有关闭 TLS 校验或改用绕过方式。环境网络域名补充只保存为草稿，保存不等于应用。

新增 **搜索结果 → 检查播放** 和 `npm run test:live`。前者接入真实现有播放器，要求音频数据可用并观察真实播放后进度前进；后者输出独立诊断 JSON，失败退出码为 2。普通用户自己的酒馆操作见 [本机实测步骤](live-playback-guide.md)。

## C / D：闭环修复和歌单导入

实际修改 `request.js`、`providers.js`、`service.js`、`library.js`、`catalog.js`、`diagnostics.js`、`online-panel.js`、`index.js`、`style.css`。

- 原有 Openverse 搜索、试听、保存、绑定链路保留。新增真实播放检查、失败后手动重新解析，强制请求确实跳过旧缓存。单来源超时、取消、429 不会使本地或其他成功来源失效。
- Audius 保持维护者 Key 条件启用；你本轮明确选择暂不提供 Key，因此没有启用正式服务。当前 SDK 指向 `https://api.audius.co/plans`；公开应用 API Key 可放前端，Bearer Token 只能留后端。文档免费方案为 10 请求/秒、50 万/月；未来以平台实际方案为准。
- 已读取的歌单按原顺序预览所有可访问曲目；超容量整批仍拒绝，新增逐首勾选、全选、清空、只选可直接播放、按剩余容量选择。必须确认所选数量后才导入，不静默丢歌。原始总数、作者、封面、平台和歌单链接随用户设置保存。
- 重复来源歌单继续复用；曲目同平台同 ID 去重，不跨平台按歌名替换录音。新导入歌单继续使用已有角色绑定界面。

**验证范围**：缓存/分页/失败隔离与数据保护通过单元测试；浏览器使用明确的接口替身与生成 WAV 验证原生播放和选择导入。没有真实 Audius 账号、真实长歌单或 Openverse 外网音频通过验收。

| --- | --- | --- | --- | --- |

| 酷狗 | 社区支持 hash/搜索/登录，不等于正式授权 | 社区实现存在，需核验完整性 | 未启用 | 需获准服务及维护，当前仅来源 |
| 酷我 | Meting 声明搜索/歌曲/歌单能力 | 本轮未验证合法稳定的完整读取 | 未启用 | 官网本次返回 500，不能据此推定全部服务停服；当前仅来源 |
| 咪咕 | 标准链接可识别 | 未确认合适的公开完整读取接口 | 未启用 | 没有把网页 200 当 API 授权；当前仅来源 |
| Spotify | 官方 Web API 需应用、令牌；oEmbed 只给有限信息，不保证专辑/歌手字段齐全 | 官方 API 按权限/模式分页；oEmbed 不是完整歌单 API | Web Playback SDK / Embed，可能受账号、Premium、地区或试听限制 | **当前政策禁止与其他服务内容整合**。候选实现默认关，不能靠拿到 Key 绕过产品限制；公开应用还需核对配额模式与资格 |

| YouTube / Music | YouTube Data API 视频搜索，不能假定存在通用 YouTube Music API | Data API playlistItems 分页、隐私和不可用条目限制 | 官方可见 IFrame Player；不能提取音频、隐藏要求的视频画面或避开广告/限制 | Data API Key 与配额由维护者管理；OAuth 用于需要授权的内容。嵌入仍受视频所有者/地区/账号限制；未实现 |
| SoundCloud | 官方 API 需应用和令牌；oEmbed 可给公开条目有限信息 | 正式 API/Widget 可提供信息，但未实测完整歌单，oEmbed 本身不给全部歌曲 | 官方 Widget 支持 play/pause/seek/volume 与事件 | **API 条款限制跨来源点播聚合及持久缓存**。本产品未确认许可，候选默认关；正式 API 文档提及 Artist Pro 应用接入与后端 client secret，不能当免费无限公共源 |
| Audius | 官方适配器已有，公开 Key 未配 | 接口能读取；本轮只有替身分页/完整性验证 | 公开非门控曲目可走官方 stream，但真实测试流请求受阻 | 维护者申请公开 Key；购买/门控/应用白名单等不绕过；当前关 |
| Openverse | 匿名公开许可音频 API，本次验证页拦截 | 不是一般歌曲平台的歌单服务 | 许可明确时读取原站音频给 HTML Audio | 不要求安装者 Key；原站授权、URL 有效性、格式、地区/网络和匿名配额仍会影响播放 |

Meting、Meting-API、MetingJS 仍是不同组件：前者是接口实现，API 是需运营的封装服务，JS 是前端组件。开源许可不等于 API 运营许可或内容授权。未复制第三方私有代码/UI，未使用来源不明公共接口作为默认后端，未共享账号 Cookie。

### 官方嵌入候选的实际代码

`platforms/embeds.js`、`providers.js`、`config.js`、`service.js`、`online-panel.js` 和 `index.js` 实现了独立候选：官方 oEmbed 元数据读取，按固定模板构造官方 iframe，不执行服务返回的 HTML。单首可在详情底部打开；无法读取歌单时，可单独打开官方歌单播放器，**不声称导入曲目**。

主音频先暂停，详情关闭、面板关闭、角色切换/退出时卸载 iframe；不让两个播放器重叠。保留平台控制、标识与可能的登录限制，提示全曲或试听由平台决定。未接官方 SDK 时不能统一进度、音量、队列，也无法可靠验证开始发声，所以不伪造状态或历史。

这些交互通过替身 iframe 的浏览器测试，**真实官方播放器发声未验证**。`embeds.spotify` 与 `embeds.soundcloud` 正式默认均为 `false`，按平台分别控制；只有平台使用条件已解决时才能启用。普通用户不需要看到这些维护开关。

## F：开发者默认曲库

修改 `platforms/builtin-maintenance.js`、`catalog.js`、`providers.js`、`scripts/update-builtin.mjs`，新增 `examples/default-library.json` 与 [中文维护步骤](default-library-guide.md)。

支持多个分享来源、批量 JSON、固定已授权公开直链及元数据、稳定 ID/URL 去重、混合来源、追加和 dry-run。非完整播放条目必须显式接受并保持 `external`/`embed` 状态；纯来源书签和不完整歌单仍拒绝。成功版本加一，失败旧文件保留，临时平台音源不写入永久清单。

正式 `builtin-tracks.js` 未添加测试歌曲。默认直链的原生播放、查看详情不自动复制、用户副本/绑定在升级后保留，均有测试。维护者提供版权依据和可用地址仍是必要输入。

## G：测试与交付口径

新增 `tests/online-upgrade.test.js` 与 5 个浏览器用例，扩充现有测试而不删除旧断言；来源书签旧用例改用仍未接入的网易云，避免把候选 Spotify 当默认可用。新增独立 `scripts/verify-online.mjs`、本机实测说明及阶段报告，更新 README/CHANGELOG/manifest/package 版本。
